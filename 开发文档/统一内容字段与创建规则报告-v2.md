# 统一内容字段与创建规则 v2

2026-11-16，根据本次用户逐项修订更新。本文件取代 v1 中相冲突的建议。

## 一、公共字段

保留 id、type、title、createdAt、updatedAt、occurredAt、deletedAt、tags、schemaVersion、data。删除公共 summary。类型需要说明时，在专属字段定义 text 或 description。

图片采用 `imageAssetIds: string[]` + `coverAssetId: string|null`。图片列表可多张；默认首张为封面。日记、便签展示多张，歌曲、影片及其他卡片默认只展示首张。单个封面 ID 不改成数组，避免所有旧调用把数组当图片路径。

ID、时间由系统创建；title 是统一标题，书籍不另建书名字段。位置与画布缩放仍属于 layout。旧数据先备份，运行兼容字段不立即删除。

## 二、最终专属字段和创建入口

| 类型 | 专属字段 | 创建入口 |
|---|---|---|
| 书籍 | author；originalAssetId、readingAssetId、originalFormat、readingFormat=markdown、parseStatus；阅读进度 progress、累计 totalReadingSeconds、上次阅读 lastReadAt、上次时长 lastSessionSeconds | 从本地书籍文件/文件夹导入，转为 Markdown。无 ISBN、来源说明、简介表单 |
| 摘录 | quote、position | 阅读器选中文字创建，直属书籍 |
| 批注 | text | 在摘录下创建，直属摘录 |
| 抄写作品 | text（目标原文）、chapterTitle、typedText（实际已抄文字）、cursor（字符位置）、status、completedAt | 原文选区、抄写界面选书/章节/整本书、已有摘录。直属书籍 |
| 旅途 | description、startDate、endDate | 空旅途、选择已有记忆点、批量照片导入后组织旅途 |
| 记忆点 | 地点名称、国家/省区/城市、地点标识、经纬度、caption、date、time、timezone、visitStatus、locationStatus、locationSource、dateSource | 地图选点、手工文字/地点、单张照片、多照片/文件夹、旅途内新增。默认一图一点，同坐标可多个点 |
| 歌单 | description、provider、sourceId | 手工空歌单、已有歌曲集合、平台导入 |
| 歌曲 | artist、album、genre、provider、sourceId、audioAssetId、durationSeconds | 平台导入、本地音频导入、无音源资料卡。取消新增歌曲链接导入路线 |
| 影片 | url、douban、status、score、scoreSource、region、genres、releaseYear | 豆瓣解析、其他来源网页、手工资料卡 |
| 日记 | text、date、mood | 手工创建；从其他合法类型入口记入今天；抄写作品生成图片。没有日历入口，没有 location |
| 便签 | text、tone、kind | 手工文字/图片；从其他合法类型入口创建 |
| 待办 | text、done、completedAt | 手工；从其他合法类型入口创建。无额外 description、dueDate、dueAt |

书籍阅读状态实际保存在现有 readerState.books[bookId] 中，按书籍 ID 关联，不在两个位置重复维护时间与进度。progress 为 0–1，显示乘 100%。lastSessionSeconds 为最近一次阅读会话累计秒数。隐藏窗口或失焦不累计。

抄写 text 固定为目标原文，typedText 保存用户实际输入，cursor 按 Unicode 字符计数，不用 UTF-16 长度把表情计为两个字。status = not_started / in_progress / completed；精确匹配目标才完成；completedAt 与 createdAt 分开，持续保存不会改首次完成日期。chapterTitle 仅用于标题展示，不要求精确回跳。保留旧 textId 只用于读取旧作品，不用于新建字段。

visitStatus 只有 visited、wish；照片导入保留 visited，手工新建默认 wish，可修改。没有 unknown。坐标不唯一，不按地点/坐标合并照片。

音乐平台信息用于导入识别，播放依赖本地缓存；无音源资料卡允许 audioAssetId=null，界面明确不能播放。平台需要的 mediaMid/fee 只作为既有协议适配信息保留，不加入用户可编辑的专属字段。

## 三、跨入口创建

从书籍、摘录、批注、作品、旅途、记忆点、歌单、歌曲、影片等内容卡可创建日记、便签、待办。来源与新内容自动保存 related 关系。同类型关联仍禁止，因此日记卡不提供“再关联日记”，便签卡不提供“再关联便签”，待办卡同理。

记入今日日记：按本机日期查已有记录，有则追加文字并建立关系，没有则新建。相同来源再次记入会追加正文，不重复增加关系。历史上同一天有多篇日记时暂使用列表中第一篇，不擅自合并其他历史日记。

上下文不复制地点。想表达地点时关联记忆点。当前位置、关联来源等信息不自动生成 location 字段。标签自动化规则本次未新增，保留手工标签。

## 四、图片与保存兼容

正式项目新增统一图片附件库 `cyber-study-content-assets-v1`（IndexedDB）：assets 存图片 Blob，items 按 type:id 存 imageAssetIds 和 coverAssetId。新增内容卡图片通过此库保存，不把大图片写入 localStorage。现有地球仪文件、影片海报和日记旧图片继续兼容读取，本次不迁移或删除原文件。

实验室独立使用自己的 state.assets，便于 JSON 导出包含示例图片；限制每张 2 MB，正式内容卡每张限制 20 MB。实验室与正式图片数据不互通。

本地音频进入桌面应用 music-cache 目录，通过 study-audio 协议读取；64 MB 限制沿用现有缓存上限，支持实际可识别的 mp3/wav/flac/aac/m4a/ogg。平台缓存也存 audioAssetId 引用。

## 五、本次实现边界

- 正式模块仍保留原有物理存储和兼容字段；这不是把整套项目搬到一个新数据库的迁移。
- 公共新字段定义由 shared/contentSchema.js 维护；实验室的新建模板与正式抄写状态计算使用该共享源。
- 新增关系保存在现有 localStorage 的 content-relations 集合，独立于旧模块内部成员数据；正式项目尚没有实验室那样的全局关系浏览器。
- 图片附件为新增统一入口，旧的日记单图按钮和影片海报按钮仍兼容保留，不假装已统一迁移历史附件。
- 真实平台登录、平台缓存权限和大规模照片导入仍需在用户桌面账号环境验收；隔离测试不使用用户私有账号。

## 六、验证记录

已执行正式项目构建；现有与新增单元测试共 32 项通过。独立浏览器窗口验证：抄写目标/已抄文字分离、字符位置、章节保存、刷新后继续；今日日记复用与文字追加、关系去重；多图片保存与首张封面；实验室关系选择器回归。未使用真实音乐平台账号进行在线缓存验收。
