# 赛博书房打包内容与用户数据清单

核对日期为 2026-11-13。本文记录当前 macOS 打包逻辑、首次启动的默认值，以及接下来设计分发包时可以采用的收录规则。

## 1. 现有 APP 和 ZIP 收录了什么

双击 [打包赛博书房.command](../../打包赛博书房.command) 会运行 [scripts/package-mac.mjs](../../scripts/package-mac.mjs)。脚本构建前端，组装 Electron APP，再把同一个 APP 压成 ZIP。ZIP 解压后得到可运行的 APP。开发源码、构建脚本和原始场景制作目录是另一种交付需求，需要单独定义源码包。

| 当前收录项 | 来源与进入包的方式 |
| --- | --- |
| 桌面运行环境 | 复制依赖中的 Electron.app，再设置应用名、版本、Bundle ID 和图标。 |
| 前端及功能默认值 | 以 `mac-package` 模式构建 `dist/`，复制到 `Contents/Resources/app/dist/`。React 界面、默认配置和代码内置内容随构建产物进入。 |
| Electron 主进程与依赖 | 复制 `package.json`、整份 `electron/`，以及网易云音乐和歌词解码所需的运行依赖树。 |
| 选定场景 | [scene.config.json](../../scene.config.json) 选中 `场景包/3D版Loft`。[vite.config.js](../../vite.config.js) 校验该目录的 `scene.json`，把清单编入前端，并按引用复制模型、纹理、音效，以及目录中存在的已登记宠物模型。当前核对到 32 个资源全部存在，覆盖当前场景的 `models/`、`sounds/`、`textures/` 内的文件。原始 `scene.json` 和 `scene.config.json` 没有以独立文件进入 APP。 |
| 内置示例书 | [sampleBooks.js](../../src/reader/sampleBooks.js) 把 `assets/books/*.txt` 全部编入前端，打包脚本另外整份复制 `assets/books/`。当前有《数字花园读书法》《深度工作的十二个夜晚》《雨夜信号》。放进这里的私人 TXT 会随包发布，其他文件也会被目录复制带入。 |

脚本的复制范围没有包含项目根的 `.user-data/`、`work/`、`朋友时间线/`、`验收截图/`、旧发行包或整份 `assets/`。场景包预览工具走单独的 `--preview` 分支，收录其启动器、说明和预构建 `web/`，输出独立的预览工具 ZIP。

## 3. 用户数据保存在哪里

未打包运行时，主进程把 `userData` 指向项目根的 `.user-data/`。正式 APP 使用 Electron 的系统默认资料目录，在 macOS 通常是 `~/Library/Application Support/赛博书房/`，实际以 `app.getPath('userData')` 为准。开发窗口可以加载本地开发服务器，正式 APP 通常加载包内 `dist/index.html`。浏览器存储按页面来源管理，同一个资料目录也可能同时存在多个来源的数据。入口见 [electron/main.cjs](../../electron/main.cjs)。

### Local Storage

通常存放在资料目录的 `Local Storage/leveldb/`。下表中的书房功能短键由 [spaceStorage.js](../../src/data/spaceStorage.js) 统一加上 `cyber-study.space.v1.` 前缀。阅读器用自己的完整键。

| 键 | 包含的用户数据 |
| --- | --- |
| `cyber-study.reader.v1`（完整键） | 上次读的书、阅读字号和行高、每本书的标题、滚动进度和更新时间。 |
| `knowledge` | 摘录、批注、书籍来源、标签、段落定位、阅读进度、创建时间和项目。 |
| `music` | 保存的歌曲、平台歌曲或歌单导入结果、标题与来源链接等。临时选择的本地音频使用对象 URL，保存时会过滤这类曲目。 |
| `musicPlaylistModes` | 各歌单的播放模式偏好。 |
| `movies` | 电影收藏和条目信息，以及海报引用。海报文件另存。 |
| `diary` | 日记文字、日期、心情、图片，也可能含从打字机保存来的作品图。 |
| `diary-prefs` | 笔型、声音、动画偏好。 |
| `memo` | 文本及图片便签、布局位置，也可能含打字机作品图。 |
| `globe` | 地球仪照片及相关记录。 |
| `typewriter` | 已保存草稿、输入文本、完稿、篇目及创建时间。 |
| `pet` | 互动后的心情、亲密度、宠物 ID、总抚摸次数、最后抚摸时间、近期抚摸时间和当日计数。 |
| `plant` | 成长、水分、浇水次数和时间、专注分钟与时段、状态更新时间。 |

### IndexedDB、登录与文件缓存

| 位置（相对于资料目录） | 内容 |
| --- | --- |
| `IndexedDB/` | 数据库 `cyber-study-books` 的 `books` 存储区保存导入书籍记录及正文。内置示例书由应用资源直接提供。见 [bookStore.js](../../src/data/bookStore.js)。 |
| `music-qq.enc`、`music-netease.enc` | 用 Electron `safeStorage` 加密的音乐平台登录 Cookie。见 [register.cjs](../../electron/music/register.cjs)。 |
| `device-identity.json` | QQ 音乐适配层按需生成的本机设备标识。见 [device-identity.mjs](../../electron/music/simple-music/device-identity.mjs)。 |
| `music-cache/` | 缓存下来的音乐音频。见 [cache.cjs](../../electron/music/cache.cjs)。 |
| `movie-posters/` | 缓存或手动上传的海报原图。见 [moviePosters.cjs](../../electron/moviePosters.cjs)。 |
| `Partitions/douban-movie/` | 豆瓣内嵌窗口的独立持久会话，包括可能的登录 Cookie、浏览器存储和缓存。 |
| 资料目录其余运行文件 | Chromium 的 Cookie、Session Storage、Cache、Code Cache、GPUCache、Preferences、网络状态、临时文件，以及可能存在的崩溃转储等。整份资料目录均排除。 |

知识工作区导出的 Markdown、打字机下载的 JPG 会保存到用户选择或系统配置的下载位置。它们也属于个人内容，即使后来手动放回项目目录。灯光切换、临时音频、面板开关等会话状态目前主要保存在界面内存中。

## 4. 用于下一版打包程序的收录规则

1. APP 从干净的暂存目录组装。允许的来源限定为 Electron 运行环境、应用清单、当次构建的前端、必要的主进程代码和依赖、图标、选定场景资源及获准随包发布的示例内容。ZIP 以这次组装完成的 APP 为唯一输入。
2. 默认按场景引用收录运行文件，并验证模型、主题、纹理和音效都在选定目录内，且文件真实路径仍在该目录内。如果要让收件人编辑场景，另提供经过筛选的场景制作包，保留 `scene.json`、可移植的选场景配置及相对目录结构。发布前确认场景模型、贴图和音频中没有混入私人素材。
3. 为内置书使用明确的发布清单，同时约束 Vite 的书籍加载和 APP 的文件复制。仅删掉 APP 中的书籍副本无法移除已经编入前端的正文。主进程目录和依赖复制也按预期路径检查，拒绝把暂存目录外的文件通过链接带入。
4. 在签名和生成 ZIP 前检查 APP 实际文件清单，再检查 ZIP 解压后的 APP。排除开发与正式运行资料、数据库、缓存、Cookie、加密凭据、设备标识、导出内容和其他未经批准的文件。禁止从现有资料目录复制一份“初始数据”。
5. 用独立的空资料目录验收。确认选定 Loft 能加载、内置示例书可读、猫咪从心情 45 和亲密度 10 开始，用户书籍、进度、批注、歌单、登录和照片为空。互动后重启确认记录只写入该测试资料目录，再用新的空资料目录确认初始值仍一致。读取同机已有资料时可能看到旧记录，因此验收要隔离资料目录。

本次核对了源码、当前场景引用和本机资料目录的文件类别，未读取私人记录正文。当前 `release/mac/` 只有预览工具 ZIP，本次未重新生成或启动主 APP，也未检查主 APP 或 ZIP 的实际内容。本文件仅记录现状和后续规则，现有打包脚本未修改。
