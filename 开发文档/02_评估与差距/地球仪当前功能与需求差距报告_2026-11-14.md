# 地球仪当前功能与需求差距报告

**报告日期：2026-11-14**  
**评估范围：基础修整、个人足迹闭环、3D 浏览升级三轮更新后的项目源码。**  
**用途：统一说明当前可以使用的功能、相对原始规划的剩余差距，以及后续实施顺序。**

## 1. 当前结论

地球仪已经从“单张照片加随机光点的展示原型”，发展为一个**本地个人照片记忆库＋真实坐标 3D 浏览器**。

当前可以完成的核心流程是：

> 导入照片 → 读取可用日期与 GPS → 在待整理区确认地点 → 在 3D 地球上浏览 → 打开地点照片 → 编辑或移入回收站 → 备份与恢复。

但当前还不是原设计所描述的完整“沉浸式记忆地球”。最大的剩余部分是：**平面地图整理、地点层级聚合、旅程及路线播放、世界风景与想去、知识库连接、书房连续转场**。

三轮工作完成的是可持续扩展的基础版本，不能据此把原设计文档中的全部第一版目标标记为已完成。本报告不使用单一完成百分比，因为各项需求的规模差异很大。

| 更新轮次 | 解决的核心问题 | 主要成果 | 被后续版本替代或延续的部分 |
| --- | --- | --- | --- |
| 第一轮：基础修整 | 随机位置、不可靠保存、日期含义不清、缺少编辑浏览 | 隐藏随机光点；失败保留输入；拍摄日期可未知；编辑地点与说明；搜索；照片放大和键盘切换 | 当时的 Local Storage 和 2 MB 限制已被第二轮替代；照片管理与浏览能力继续保留 |

## 3. 当前支持的全部主要功能

### 3.1 入口与模式切换

- 从书房地球仪入口打开模块，默认进入“3D 浏览”。
- 可切换到“照片整理”，使用导入、编辑、定位、回收站和备份功能。
- 地点照片卡提供“整理这张照片”，直接进入相应记录的编辑状态。
- 模块提供返回书房入口；整理中有未保存内容时，会在可能丢弃编辑的操作前提醒。

**边界：** 当前是独立面板中的 3D 浏览，不是书房实体模型连续放大为地球的无缝转场；也没有额外的操作系统级全屏按钮。

### 3.2 照片导入与旧数据迁移

- 支持单张、多张和递归文件夹导入。
- 单个文件限制为 80 MB；这只是导入大小上限，不代表已验证任意超大像素图片的内存表现。
- 支持可解码的 JPEG、PNG、WebP；文件选择也接受 HEIC/HEIF，但成功与否取决于实际解码能力，不能保证通用支持。
- 对每张照片计算文件哈希，重复文件自动跳过；已有副本在回收站时提示可恢复。
- 导入过程显示进度；单张失败继续处理其他照片；结果报告区分成功、失败和跳过。
- 成功照片逐张保存，不需要等待整批全部成功才落库。
- 提供“迁移旧版照片”入口，将原 Local Storage 图片迁入本地文件库。
- 相同旧记录重复迁移不会重复创建；旧随机经度不转成真实坐标；原 Local Storage 数据保留作为回退。

**边界：** 没有暂停、取消、断点续传及崩溃后的任务续跑；重复照片目前自动跳过，没有“作为独立副本导入／重新关联”选择；未实现相似图片识别。旧数据保留会占用额外空间，当前没有专门清理旧副本的入口。

### 3.3 日期、位置与待整理

- 读取 JPEG EXIF 中可用的拍摄日期及 GPS 经纬度。
- 无法读取的日期保持未知，不把文件日期或导入当天静默认定为拍摄日期。
- 拍摄日期与导入时间分开记录、显示；旧版日期保留待核实标记。
- 带 GPS 的照片先作为候选，确认后才进入“我的足迹”。
- 没有位置的照片保存在待整理区，不随机放到地球上。
- 支持手动填写地点名称、纬度、经度，并验证坐标范围；零度坐标可用。
- 内置 28 个离线城市中心候选，可按名称查找；明确提示这是近似城市中心，不是具体拍摄位置。
- 支持单张、多张勾选，以及选择当前筛选结果后批量指定地点。
- 批量确认前显示照片数量、目标地点和坐标。
- 保存位置来源，例如照片 GPS、城市中心、手动填写；修改坐标后需要重新确认。

**边界：** 没有地图选点、联网地名搜索、GPS 自动转地点名称；离线目录不是全球国家／城市数据库。当前足迹准入主要检查位置，拍摄日期未知但位置已确认的照片仍可进入足迹；这与原文档第 25 节“没有日期或位置均待确认、不上球”的表述存在差异，应在后续需求中统一。

### 3.4 文件保存、备份与恢复

- 原图复制到应用管理的本地资料目录，移动或删除导入来源文件不影响已有浏览。
- 分别保存原图、长边不超过 1800 像素的预览图、长边不超过 360 像素的缩略图。
- 保存文件指纹及来源信息；记录索引以临时文件加重命名方式写入，减少写入中断导致索引损坏的风险。
- 读写失败有明确提示；不会把损坏的索引静默当成空库并覆盖。
- 可以导出完整目录备份，包含原图、预览、缩略图、坐标、说明和回收站记录。
- 备份前提示包含精确位置；备份清单在图片复制完成后才写入。
- 恢复时校验原图哈希，并重新生成预览及缩略图。
- 恢复采用按记录 ID 合并：已有同编号记录保持不变，补入缺少的记录。

**边界：** 没有只备份部分照片、排除精确位置、只备份缩略图等选项；没有定时备份或备份版本浏览。合并恢复不等同于回滚整个资料库，也不会覆盖当前同编号记录的编辑。来源文件移动已通过“复制保管”解决，但应用管理目录自身损坏时，仍缺少逐图状态检测、重新关联或专门修复入口。

### 3.5 照片整理与回收站

- 提供“待整理”“我的足迹”“全部照片”“回收站”四类视图。
- 按地点、拍摄日期、说明或文件名搜索照片。
- 编辑地点文字、坐标、拍摄日期和照片说明。
- 预览照片、全屏看图、前后切换及 Esc 关闭；地点放大浏览只遍历该地点的照片。
- 照片可以移入回收站并恢复；恢复保留原有图片和地点信息。

**边界：** 第一轮曾支持在编辑时重新选择照片；当前第二、三轮的编辑表单主要修改元信息，没有替换已存图片文件的入口。没有标签、独立地点档案、批量删除、永久删除及派生文件清理，也没有旅程或知识引用的恢复关系。

### 3.6 3D 地球与地点浏览

- 使用真实 3D 球体、陆地轮廓和经纬网，地图资源随应用离线保存。
- 只有已确认、未删除且经纬度有效的照片生成球面光点。
- 使用真实经纬度投影；同一坐标照片合并为一个地点，180° 与 −180° 经度按同一位置处理。
- 支持拖动旋转、滚轮缩放、放大／缩小按钮、回到全球视角。
- 提供自动旋转开关，用户开始操作会停止自动旋转；进入后台也停止旋转。
- 提供方向按钮，作为不拖动鼠标也能转动地球的替代方式。
- 点击球面光点或地点列表，镜头靠近目标地点，旁边展开纸色照片卡。
- 照片卡显示地点、日期、说明、坐标及近似城市中心提示；支持同地点照片切换和进入整理。
- 支持搜索已有地点或照片说明、清空查询、分批显示地点列表（每批 40 个）。
- 显示已收录地点数和已确认照片数；没有虚构国家、城市或旅程统计。
- 适配窄窗口，照片区域可移到地球下方。

**边界：** “同坐标合并”不是国家／区域／城市层级聚合；附近但坐标不同的照片仍各自成点。没有双击空白区域放大、地点标签体系、世界风景图层、完整图层开关、旅程路线或时间轴。底图面向全球浏览，不是街道地图或精确海岸测绘图。

### 3.7 动态效果、性能与异常处理

- 遵循系统减少动态偏好，也可手动切换；减少动态时停止自动旋转，镜头直接定位，照片卡不做入场运动。
- 静止时按需渲染；限制画布像素比；使用实例化光点；3D 模块延迟加载。
- 切换整理模式会卸载 3D 画布。
- 3D 创建失败或上下文丢失时显示说明与重试入口，地点列表和照片浏览保留。
- 保留空库、无搜索结果、导入部分失败、存储失败等状态反馈。

**边界：** 没有地球模块专门的高／中／低性能档位、远近聚合和大规模视野管理；没有独立图片后台处理队列、导入暂停续跑或可靠的空间不足恢复机制。未验证万级地点或低性能实体设备的帧率与内存上限。

### 4.1 几个不能混为一谈的概念

1. **真实 3D 地球不等于连续空间转场。** 当前地球内部能靠近地点，书房到地球仍是打开模块。
2. **同坐标合并不等于远近层级聚合。** 不会根据缩放自动把许多附近光点变为一个城市或区域。
3. **照片整理不等于平面地图整理。** 当前没有可点击选位置的地图。
4. **个人足迹不等于“想去 → 已去过”。** 后者还需要独立状态、时间记录和转换确认。
5. **离线地球底图不等于世界风景。** 底图只是地理表面，没有精选风景照片或公共地点内容。
6. **本地备份不等于版本回滚和彻底删除。** 当前恢复合并记录，回收站保留文件。
7. **照片说明不进入知识库，不代表已经实现知识库连接。** 当前只满足“不自动写入”的边界。

## 5. 与《项目功能差距与迭代可行性报告》的差距变化

总报告第 3.6 节记录的是三轮更新前的状态，以下旧判断已被新的实现替代。

| 旧总报告中的状态／缺口 | 三轮更新后的状态 | 剩余缺口 |
| --- | --- | --- |
| 照片地点只有文字，随机经度和序号排列 | 已改为用户确认的真实经纬度；旧随机位置不作为足迹 | 地图选点、地名服务、独立地点实体 |
| 单张选择，限制 2 MB，图片放在 Local Storage | 新库改为本地文件，支持多张／文件夹；单张上限 80 MB | 大批量后台处理与任务恢复 |
| 缺少原图／预览／缩略图和哈希 | 已有三层图片和文件哈希 | 相似图片识别、原图损坏重关联 |
| CSS 球体和滑杆 | 已替换为真实 3D 地球和交互控制 | 连续转场、层级聚合与更细的性能分级 |
| 缺少真实投影和地点搜索 | 已有真实投影和已有地点搜索 | 全球／精确地名及分类搜索 |
| 离线能力只限已有图片在本地 | 已有离线地球、托管照片、28 城市候选 | 更广离线地理目录、尚未建设的旅程和风景离线能力 |
| 回收站和最小备份恢复待做 | 已有照片回收站与完整备份合并恢复 | 永久删除、关系恢复、版本策略、选择性备份 |
| 旅程、风景、想去、知识关联缺失 | 这些模块仍未实现 | 仍是下一阶段的完整新增工作 |

### 5.1 原迭代建议的执行情况

- **P0：取消随机坐标并标记旧数据——核心已落实。** 新流程不生成随机位置，迁移后旧照片待确认。旧资料不会在未点击迁移时自动改写。
- **P1：真实地点和照片归档——核心闭环已落实，完整目标仍有缺项。** 已能导入、确认、保存、重开和浏览；地图选点与原图重新关联未实现。
- **最小备份恢复提前——已落实。** 当前采用完整目录备份及按 ID 合并恢复。
- **先二维整理，再 3D——实际顺序有所调整。** 已先实现城市选择／坐标整理，再完成 3D；二维地图整理仍待补。
- **Place、PhotoAsset、Journey 模型——只落实了照片和位置字段的基础。** 地点当前按照片坐标在浏览时归组，尚无完整独立地点及旅程关系模型。
- **沉浸体验深化——部分落实。** 真实地球、照片卡、减少动态已有；连续转场、聚合、路线及公共内容仍缺。

另外，地球仪设计第 29 节“只有打包成品，缺少可编辑源码”的结论已经过时；旧总报告对此已作纠正。当前项目确实具有可编辑源码，三轮开发也已基于源码完成。

## 6. 剩余功能的建议推进顺序

以下为实施建议，不是已经承诺的工期或已经完成的功能。

| 建议顺序 | 工作包 | 主要内容 | 完成后可验证的结果 |
| --- | --- | --- | --- |
| 1 | 地点整理补齐 | 平面地图选点、更广离线城市、同名候选、精确地名搜索适配层 | 无 GPS 的普通用户可以不查经纬度就为照片定位 |
| 2 | 照片库稳定性 | 任务取消／暂停恢复、更多元数据、损坏图片检测与修复、重复处理选择 | 多种真实照片和大批量导入可控，错误可恢复 |
| 3 | 地点模型与聚合 | 独立地点记录、照片关联、近邻和城市／区域聚合、密集点验收 | 图库增大后球面仍清楚可点，修改地点有稳定关联 |
| 4 | 手动旅程 | 建旅程、命名、加入移出照片、排序 | 用户可以先手动整理一次旅行，不依赖自动算法 |
| 5 | 旅程建议与播放 | 时间空间建议、确认、拆分合并、路线、时间轴 | 能按照片顺序回看一趟旅程，不伪装真实交通路线 |
| 6 | 想去与世界风景 | 先建想去状态，再接小规模授权明确风景包和双图层 | 公共内容与个人照片分开，可确认转为已去过 |
| 7 | 知识库连接 | 记忆笔记、引用、回跳与导出 | 主动写下的旅行笔记能可靠连接原照片和旅程 |
| 并行打磨 | 入口转场与交付 | 连续进入退出、低性能设备检查、安装版打包回归 | 使用过程连贯，实际分发版本与源码能力一致 |

如果下一轮只选择一项，建议优先做**地图选点与地点整理**：它直接降低导入个人照片后的操作门槛。转场更容易带来视觉提升，但不会解决“没有 GPS 时该怎么放照片”的实际问题。

## 7. 测试证据与尚未验证的范围

### 已有证据

- 数据层及地理投影测试共 11 项通过，覆盖导入去重、重开、位置确认、回收站、迁移、备份恢复、损坏数据、JPEG EXIF 和球面坐标。

- 第三轮浏览器检查使用虚构照片，验证真实 WebGL、光点点击、地点照片卡、全屏序列、搜索、旋转中断、减少动态、模式切换、窄窗口、空库以及渲染中断重试。
- 三轮的生产构建检查通过；第三轮有全球视角、地点照片及窄窗口截图。

### 不能据此推断的结论

- 未完成所有真实相机／手机格式、HEIC 及方向信息的兼容验收。
- 未完成大规模真实个人图库和低配置实体设备压力测试。
- 浏览器界面测试中使用了模拟资料接口，不能等同于整套正式安装版端到端验收。
- 地球仪范围静态检查通过，不代表整个赛博书房的所有历史 UI 差异已经修复。
- 本次报告基于三轮测试记录和源码核对，没有重新运行全部测试或扫描用户私人照片。
