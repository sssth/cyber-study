# 画质与性能评估

当前启用场景：3D版Loft v0.2。目录约 173 MB（包含源资源，不等于显存占用）。

## 代码中的主要负载

| 来源 | 影响 | 当前处理及后续建议 |
|---|---|---|
| Furniture3DLayer 的全部 GLB 与 useGLTF 缓存 | 加载、解码、内存、几何处理；复杂网格也增加鼠标拾取开销 | 当前档位保持模型完整；下一阶段应提供 LOD 模型，按距离与档位选择 |
| SceneTextures 与材质贴图克隆 | 纹理解码与显存；纹理数量不能换算成准确显存 | 需要离线缩小贴图、KTX2 压缩与按需加载；不能仅缩小画布解决 |
| Canvas 像素倍率 | GPU 像素计算与渲染缓冲区 | 三档上限 1 / 1.5 / 2；实际不超过设备倍率 |
| ThemeLighting 阴影 | 阴影纹理、额外绘制 | 已有静态阴影缓存；低档关闭，中档最多 1024，高档最多 2048，且不超过资源指定尺寸 |
| OutdoorRain | 每帧 CPU 更新及缓冲上传、透明绘制 | 雨滴数量 25% / 60% / 100% |
| ThemeGlows 与透明材质 | 透明混合、像素叠加 | 低档关闭光晕 |
| 环境反射 PMREM | 生成环境贴图和材质采样 | 现有环境按配置变化生成并清理，暂保持一致 |
| 主场景持续渲染 | 空闲时仍消耗算力 | 后续可在阅读器遮挡与后台时暂停，需与雨滴、相机动画协调 |
| CareModelPreview | 独立 WebGL 上下文与渲染缓冲 | 已采用按需渲染；本次档位仅作用于主书房 |
| 阅读器、音乐与音频 | DOM 布局、文件解码、音频处理 | 不由画质档位修改，性能问题需分别分析 |

## 当前交互与检测

右上角互动菜单 → 画质与流畅度。默认中档，立即生效并保存本地。保存失败时提示。切换档位清除旧检测，避免结果与设置错配。

检测预热 2 秒后采集 8 秒，后台样本重置；显示平均 FPS、P95 帧间隔及 Three.js 渲染统计。55 FPS 以上标为流畅，30–54 为一般，低于 30 为卡顿。这只是以约 60 FPS 为目标的当前视角筛查，受屏幕刷新率、窗口尺寸和其他进程影响，不代表 GPU 使用率、显存余量或整机场景基准。不同档位应保持相同窗口、视角和日夜条件再比较。

## 验证范围

已检查参数传递、默认档位回退、本地存储错误反馈、检测重置与阴影资源释放。环境未提供 node/npm，生产构建无法执行；尚未进行浏览器实机交互与画面验证。通用 UI 静态审计发现项目既有表单控件归属等问题，未将其混入本次功能改动。不能据此声称已通过构建或实测性能提升。
