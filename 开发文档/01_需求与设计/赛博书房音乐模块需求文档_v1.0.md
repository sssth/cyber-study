## 2 产品定位

音乐模块定位为赛博书房中的个人音乐收藏室，用于收藏、陈列和播放用户最喜欢的歌曲与专辑。

本模块不取代 QQ 音乐、网易云音乐等专业音乐软件，不承担音乐发现、社区、评论、榜单、复杂歌单编辑等完整平台功能。产品重点是让用户用较低的管理成本，把来自音乐平台或个人音频文件的珍爱音乐整理成具有唱片收藏感的个人空间。

核心体验包括：

1. 从 QQ 音乐和网易云音乐导入用户喜欢的歌曲或专辑。
2. 上传本地音频文件，并自动补充歌手、专辑与封面信息。
3. 以唱片架方式陈列专辑，形成具有仪式感的浏览体验。
4. 以紧凑播放器加完整列表的方式满足日常播放和查找需求。
5. 尽量自动完成归组、匹配和同步，避免把管理压力转移给用户。

## 3 目标与非目标

### 3.1 产品目标

- 提供陈列模式与列表模式两种互补的音乐浏览方式。
- 保留现有 QQ 音乐和网易云音乐导入能力，并整合为统一入口。
- 支持用户上传本地音频文件夹或音频文件。
- 自动读取并匹配音乐元数据和封面，同时保留来源与匹配状态。
- 按来源筛选、按专辑归组并分页展示，避免所有音乐混在一条长列表中。
- 保留现有播放能力，优化播放界面和列表空间利用率。

### 3.2 本期非目标

- 不实现站内音乐社区、评论、关注、排行榜或推荐算法。
- 不实现复杂歌单编排、多人协作歌单或专业音频编辑。
- 暂不支持从 QQ 音乐、网易云音乐和本地文件以外的来源导入。
- 不要求用户手动粘贴大量歌曲或歌单链接。
- 不绕过音乐平台权限、付费限制或数字版权保护。
- 不在同步时自动删除已经进入赛博书房的收藏。

## 4 用户与核心场景

### 4.1 目标用户

希望在赛博书房中收藏少量或中等规模的个人最爱音乐，并重视封面、专辑关系和浏览氛围的用户。

### 4.2 核心场景

1. 用户进入音乐模块，在唱片架上浏览已收藏专辑。
2. 用户点击唱片封面，查看唱片抽出动画并开始播放。
3. 用户切换至列表模式，快速查找、筛选和连续播放歌曲。
4. 用户从 QQ 音乐或网易云音乐导入喜欢的歌曲或喜欢的专辑。
5. 用户上传本地音频，系统自动匹配歌手、专辑和封面。
6. 用户手动重新同步音乐平台收藏，但已导入内容不会因平台侧变化而自动消失。
7. 用户只在匹配结果不确定时进行少量人工确认。

## 5 信息架构

音乐模块使用统一收藏库，不为不同来源建立互相隔离的页面。来源用于筛选、同步和追溯，不改变音乐在收藏库中的基本结构。

### 5.1 页面顶部固定区域

页面顶部应包含以下元素：

- 页面名称：唱片收藏室。
- 搜索框：支持按歌曲名、歌手名和专辑名搜索个人收藏。
- 来源筛选：全部、QQ 音乐、网易云音乐、我的上传、待确认。
- 视图切换：陈列模式、列表模式。
- 导入音乐主按钮：位于页面偏右区域。
- 返回书房按钮：保留现有返回能力。
- 重新同步按钮：仅在当前来源为 QQ 音乐或网易云音乐时显示。

### 5.2 页面状态记忆

- 用户首次进入音乐模块时，默认使用陈列模式。
- 后续进入时，恢复用户上次使用的视图模式。
- 同时恢复上次选择的来源筛选、分页位置和陈列浏览位置。
- 页面状态记忆不应影响当前播放进度和播放队列的持久化策略。

## 6 陈列模式

### 6.1 陈列单位

- 一张唱片代表一张专辑，不代表单首歌曲。
- 从平台导入的喜欢歌曲应按其专辑信息自动归组。
- 用户导入喜欢的专辑时，应直接生成一个专辑陈列单位。
- 本地音频无法可靠确定专辑时，作为独立唱片陈列。
- 同一专辑来自不同来源时，优先合并为一个专辑实体，同时在歌曲层保留各自来源。

### 6.2 唱片架浏览

- 专辑沿唱片架横向排列，当前选中专辑位于视觉中心并适当突出。
- 唱片架支持左右浏览、滚轮或触控板横向移动以及分页。
- 不一次渲染全部唱片；按页或虚拟列表方式加载。
- 当前专辑至少显示封面、专辑名、歌手、年份和曲目数。
- 来源不是陈列卡片的主要视觉标签；只有在需要解释来源或同步状态时才显示。

### 6.3 唱片抽取与播放

1. 用户选择某张唱片时，唱片或封套进入居中状态。
2. 用户点击封面，黑胶唱片从封套中滑出。
3. 用户再次点击唱片或点击播放按钮，进入放大的播放状态并开始播放。
4. 播放状态下唱片持续旋转；暂停时可停止旋转或改为极慢速，具体动效保持统一。
5. 用户返回唱片架时，唱片收回封套并恢复原来的浏览位置。

### 6.4 专辑详情

- 点击专辑信息可查看该专辑在个人收藏中的歌曲列表。
- 详情页或展开层只显示用户已收藏的曲目，不伪装成平台完整专辑，除非数据源明确提供完整专辑信息。
- 支持播放专辑中的收藏曲目和从指定曲目开始播放。
- 支持查看来源、导入时间和封面来源，但这些信息默认弱化，不干扰主视觉。

## 7 列表模式

### 7.1 布局调整

当前版本采用左侧大播放器、右侧狭长歌单的双栏结构。歌单较长时右侧持续向下滚动，左侧出现大面积空白。本期应改为上下结构。

新布局要求：

- 页面上部为横向紧凑播放器。
- 播放器中的唱片缩小，但仍需清晰显示封面和旋转状态。
- 导入音乐入口位于页面顶部偏右，不占用歌单列表的纵向空间。
- 已导入的专辑和歌曲列表位于紧凑播放器下方。
- 下方列表使用内容区域的完整宽度，不再限制在右侧窄栏中。
- 页面滚动时，播放器可固定在顶部或收缩为迷你播放条，但不得遮挡列表主要内容。

### 7.2 紧凑播放器

紧凑播放器至少包含：

- 缩小的旋转唱片与封面。
- 当前歌曲名、歌手和专辑名。
- 播放或暂停、上一首、下一首。
- 播放进度、当前时间和总时长。
- 当前播放来源或本地文件状态提示。
- 播放模式：顺序播放、随机播放、单曲循环。

### 7.3 列表内容

- 列表默认按专辑归组，专辑可展开或收起曲目。
- 支持切换为按歌曲查看；此切换属于辅助浏览，不改变陈列模式的专辑单位。
- 列表遵循当前来源筛选，不将 QQ 音乐、网易云音乐和本地上传强制混在同一页。
- 每个来源独立分页，切换来源时保留各自分页位置。
- 歌曲行至少显示歌曲名、歌手、专辑、时长和播放按钮。
- 鼠标悬停或选中时可显示来源、导入时间和匹配状态等次要信息。

## 8 导入入口

### 8.1 统一入口

点击页面偏右的导入音乐按钮，展开以下三个选项：

1. 从 QQ 音乐导入。
2. 从网易云音乐导入。
3. 上传本地音频。

现有 QQ 音乐和网易云音乐导入功能不得删除，应迁移到统一入口中，并保留现有可用的登录或读取方式。

### 8.2 平台导入原则

- 用户不需要逐首粘贴歌曲链接或反复整理歌单。
- 导入目标为用户喜欢的歌曲和用户喜欢的专辑。
- 平台侧已有歌名、歌手、专辑和封面时，应直接使用平台数据。
- 导入前显示预计导入数量；导入后显示成功、跳过、重复和失败数量。
- 对重复歌曲执行去重，不重复创建收藏记录。
- 导入过程不得因单首歌曲失败而整体中断。
- 只使用合法、授权且当前可用的平台能力，不绕过登录、付费或版权限制。

### 8.3 平台重新同步

- QQ 音乐和网易云音乐均提供手动重新同步按钮。
- 同步用于新增歌曲、补充元数据和更新可变信息。
- 平台侧取消喜欢的歌曲，不得在赛博书房中自动删除。
- 如需删除，必须由用户在赛博书房内明确操作。
- 同步结果应生成简洁报告，包括新增、更新、跳过和失败数量。
- 登录失效时提示用户重新连接，不影响已经导入内容的浏览。

## 9 本地音频上传与自动匹配

### 9.1 上传方式

- 支持选择单个或多个音频文件。
- 支持选择包含音频文件的文件夹，并递归或按当前既有规则读取。
- 支持格式至少沿用当前版本：MP3、WAV、FLAC、AAC、M4A、OGG、OGA、OPUS、WEBM。
- 导入过程显示已扫描、已导入、重复、失败和待确认数量。

### 9.2 原始信息保留

- 不修改用户原始音频文件。
- 保存文件绝对路径或应用可恢复的本地文件引用。
- 保存文件大小、修改时间和可用于去重的哈希。
- 保存音频内嵌标签和封面原始读取结果。
- 本地上传歌曲的展示歌名默认使用清洗后的文件名，不因网络匹配而静默覆盖。

### 9.3 匹配顺序

系统按以下顺序获取元数据：

1. 读取音频内嵌标签，包括标题、歌手、专辑、年份和内嵌封面。
2. 使用文件名、内嵌标题、歌手和时长生成检索条件。
3. 从合法可用的音乐元数据来源检索候选结果。
4. 根据标题相似度、歌手相似度、专辑信息、时长差和版本信息计算匹配置信度。
5. 获取可合法使用或缓存的专辑封面，并记录封面来源。

### 9.4 置信度处理

- 高置信度：自动采用歌手、专辑和封面；歌曲展示名仍默认使用文件名。
- 低置信度或存在同名歌曲、翻唱、现场版等歧义：进入待确认列表。
- 无结果：使用默认唱片封面，歌手和专辑标记为未知，并进入待确认列表。
- 待确认状态不阻止播放，也不强迫用户立即处理。
- 用户确认或修正后，保存选择结果和人工修正记录；后续重新扫描不得静默覆盖。

### 9.5 待确认界面

- 待确认作为来源筛选中的独立入口。
- 每条记录显示本地文件名、候选歌手、候选专辑、候选封面、置信度和匹配依据。
- 用户可接受推荐、选择其他候选、保留未知或稍后处理。
- 支持批量接受高相似候选，但不得默认批量覆盖人工修正。

## 10 数据组织与去重

### 10.1 核心对象

开发实现中至少应区分以下对象：

- Track：歌曲或本地音频记录。
- Album：专辑或无法归组时生成的单曲专辑容器。
- Artist：歌手或表演者。
- SourceRecord：QQ 音乐、网易云音乐或本地上传的来源记录。
- ImportBatch：一次导入或同步任务。
- MatchCandidate：本地歌曲的候选匹配结果。
- PlaybackState：当前歌曲、队列、进度和播放模式。

### 10.2 建议字段

歌曲记录建议至少包含：

- 内部唯一 ID。
- 展示歌名。
- 原始文件名或平台原始歌名。
- 歌手 ID 和歌手名。
- 专辑 ID 和专辑名。
- 时长。
- 来源类型与来源侧 ID。
- 本地文件引用或平台播放引用。
- 导入时间与最近同步时间。
- 匹配状态、匹配置信度和人工确认状态。
- 封面地址、本地缓存地址和封面来源。

### 10.3 去重原则

- 优先使用同平台稳定 ID 判断重复。
- 跨平台或本地文件使用标准化歌名、歌手、专辑和时长组合判断。
- 本地文件同时使用文件哈希辅助判断。
- 无法确认是否重复时，不自动合并；标记为可能重复供后续处理。
- 合并歌曲时不得丢失来源记录和导入批次信息。

## 11 播放规则

### 11.1 播放队列

- 从陈列模式播放专辑时，队列包含该专辑中用户已收藏的歌曲。
- 从列表模式播放单曲时，队列依据当前筛选、排序和分页上下文生成。
- 切换陈列或列表模式不应中断当前播放。
- 切换来源筛选不应停止当前播放，但可改变后续新建队列的范围。

### 11.2 播放状态

- 播放、暂停、进度、当前曲目和播放模式在两个界面中保持一致。
- 用户返回书房后，如现有产品策略允许，音乐应继续播放；不得因关闭音乐面板而意外停止。
- 本地文件移动、删除或不可访问时，跳过该曲目并明确提示，不阻塞整个队列。
- 平台歌曲因权限、网络或接口失效无法播放时，保留收藏记录并显示不可播放原因。

### 11.3 动效与性能

- 旋转唱片只在可见且正在播放时运行完整动画。
- 大量专辑使用分页、懒加载或虚拟化，避免一次加载全部封面。
- 切换模式和来源时应保持当前音乐连续播放。
- 动效应服务于唱片收藏体验，不应造成按钮延迟、文本难读或低性能设备明显卡顿。

## 12 空状态与异常处理

### 12.1 空收藏

首次进入且没有音乐时，展示简洁说明和导入音乐按钮，并提供 QQ 音乐、网易云音乐、本地音频三个入口。不要显示空唱片架或无意义的大面积装饰。

### 12.2 常见异常

- 平台未登录或授权失效：提示重新连接，保留既有收藏。
- 网络不可用：允许浏览已缓存封面和本地音乐；平台同步进入可重试状态。
- 部分导入失败：完成其余项目并生成失败清单。
- 封面获取失败：使用默认唱片封面并允许稍后重试。
- 本地文件丢失：标记不可访问，提供重新定位入口，不直接删除记录。
- 元数据来源返回冲突：保留候选和匹配依据，进入待确认。
- 同步任务重复触发：同一来源同一时间只运行一个同步任务。

### 12.3 过程记录

每次导入或同步应记录任务状态、开始与结束时间、来源、数量统计、失败原因和可重试项。日志用于故障排查，不应在普通用户界面暴露过多技术信息。

## 13 迁移要求

- 保留当前版本已经导入的 QQ 音乐和网易云音乐记录。
- 保留现有播放能力、播放模式和本地文件夹导入能力。
- 旧数据迁移后应补充来源字段和专辑归组，不得要求用户重新导入全部内容。
- 现有封面可继续使用；缺失封面进入补充匹配流程。
- 迁移前建议备份当前音乐数据和缓存。
- 新版首次启动应执行可恢复的数据迁移，并记录迁移结果。

## 14 交互与视觉约束

- 延续赛博书房当前深色、青色描边和沉浸式界面语言，不使用通用音乐软件模板覆盖现有风格。
- 唱片、封套和专辑封面是陈列模式的视觉主体。
- 图片不得溢出封套或卡片，文字不得与唱片和控制按钮重叠。
- 列表模式优先保证信息密度和可读性，避免每首歌曲都使用过大的卡片。
- 导入、同步、删除等管理功能弱化处理，不应压过浏览和播放。
- 来源标签仅在有助于筛选、同步或故障解释时出现，不重复堆叠。
- 视觉调整不得改变返回书房、播放控制等已有核心交互。

## 15 验收标准

### 15.1 页面与模式

- [ ] 首次进入默认显示陈列模式。
- [ ] 再次进入可恢复上次使用的模式、来源筛选和浏览位置。
- [ ] 陈列模式以专辑为单位，不重复展示同一专辑的多张同封面唱片。
- [ ] 唱片支持抽出、播放、旋转和收回动画。
- [ ] 切换陈列和列表模式时音乐不中断。
- [ ] 列表模式播放器位于上方，歌曲列表占据下方完整内容宽度。
- [ ] 长列表滚动时不再出现左侧大面积无效空白。

### 15.2 来源与导入

- [ ] 页面偏右位置存在统一导入音乐入口。
- [ ] 入口包含 QQ 音乐、网易云音乐和本地音频三个选项。
- [ ] 现有 QQ 音乐与网易云音乐导入能力未被删除。
- [ ] 平台导入可获取喜欢的歌曲或喜欢的专辑。
- [ ] 平台重新同步只新增或更新，不自动删除赛博书房收藏。
- [ ] 导入任务显示成功、重复、跳过、失败和待确认数量。
- [ ] 单条失败不会中断整个导入任务。

### 15.3 本地音频与匹配

- [ ] 支持当前版本列出的音频格式和文件夹导入。
- [ ] 不修改用户原始音频文件。
- [ ] 展示歌名默认使用清洗后的文件名。
- [ ] 高置信度结果自动补充歌手、专辑和封面。
- [ ] 低置信度结果进入待确认，但仍可播放。
- [ ] 人工确认结果不会被后续自动匹配覆盖。
- [ ] 封面和元数据均可追溯来源。

### 15.4 数据与稳定性

- [ ] 同平台重复同步不会重复创建歌曲。
- [ ] 同一专辑的歌曲能够正确归组。
- [ ] 删除、移动本地文件后，应用能标记异常并继续播放其他歌曲。
- [ ] 登录或网络失效不会导致既有收藏消失。
- [ ] 大量专辑通过分页或虚拟化加载，页面无明显卡顿。
- [ ] 每次导入、同步和迁移均有可查的结果记录。

### 15.5 视觉检查

- [ ] 在常用窗口尺寸下，封面、唱片、文字和按钮无重叠或溢出。
- [ ] 列表模式中的歌曲信息完整可读，不因窄栏被过度截断。
- [ ] 页面滚动、唱片动画、来源切换和弹层无明显错位。
- [ ] 至少完成陈列模式、列表模式、空状态、待确认和导入结果的截图级检查。

## 16 建议实施阶段

### 阶段一 数据与现有能力整理

- 盘点当前 QQ 音乐、网易云音乐和本地导入数据结构。
- 建立统一 Track、Album、SourceRecord 和 ImportBatch 模型。
- 完成旧数据备份、迁移和去重策略。

### 阶段二 列表模式重构

- 将当前左右双栏改为上方紧凑播放器和下方全宽列表。
- 建立来源筛选、专辑归组、分页和状态记忆。
- 保证播放状态在布局变化时不中断。

### 阶段三 陈列模式

- 实现专辑唱片架、居中选中、抽取和收回动画。
- 实现专辑详情和放大播放状态。
- 完成大量封面的懒加载与性能优化。

### 阶段四 导入与同步

- 统一 QQ 音乐、网易云音乐和本地音频入口。
- 实现平台手动重新同步和结果报告。
- 实现本地音频扫描、元数据读取和增量导入。

### 阶段五 自动匹配与待确认

- 接入合法可用的元数据与封面来源。
- 实现置信度计算、候选结果和人工确认。
- 保存封面来源、匹配依据和人工修正记录。

### 阶段六 验证与交付

- 执行功能测试、数据迁移测试和重复同步测试。
- 对关键页面进行浏览器或应用截图级视觉检查。
- 验证大量专辑、离线状态、登录失效和本地文件丢失等异常场景。

## 17 开发评审时需要确认的技术事项

以下事项不改变本需求方向，但开发开始前应结合现有源码确认：

1. QQ 音乐与网易云音乐现有导入能力的授权方式、可读字段和稳定性。
2. 平台歌曲在桌面应用中的合法播放方式及不可播放状态处理。
3. 当前音乐数据、封面缓存和播放状态实际保存位置。
4. 本地文件夹权限在 macOS 打包后的持久化方式。
5. 可使用的音乐元数据和封面来源、许可范围、调用限制和缓存规则。
6. 跨平台同一歌曲与同一专辑的去重准确率及人工纠错入口。
7. 唱片架动画在 Electron 与当前前端技术栈中的性能预算。

开发评审完成后，应将上述技术选择补充到实现方案中，不应通过删减核心体验来默认规避。
