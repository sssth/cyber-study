# AI 检索表达式转换约定

## 一次请求的边界

用户点击独立的 AI 侧栏按钮或按 ⌘⇧D，在小窗内选择「检索表达式转换 AI」，输入描述并提交。书房取出描述，通过 `window.cyberStudy.ai.chatCurrent({system, messages})` 调用当前配置的模型。模型收到两段文本：下节的固定说明作为 system，一份序列化的 JSON 作为唯一一条 user 消息。模型返回候选表达式，书房在本地校验并执行，结果始终由当前页面产生。

每次重新发送完整的必要背景。相同页面、相同模式下复用同一份字段说明。**按页面选字段，不按用户原话猜字段。** 例如“没填地点”可能涉及地点、城市或图片存在性，一次给齐当前范围的可选字段，就能避免应用在调用前猜错。知识库跨实体时发送当前范围全部可选命令，公共字段只列一次并标明适用实体，专属字段使用斜杠菜单实际插入的命令名。声明范围越小，请求自然越短。

## 固定说明（每次原样作为 system 发送）

实际发送的固定文本见[表达式转换提示词](../src/search/expressionPrompt.txt)。


## 每次生成的 user 消息

| 内容 | 取值来源和发送时机 |
|---|---|
| scope、types、related | 当前前台页面的业务名称、该范围可用的 TYPE 值及含义、是否启用一层关联。单书阅读等不支持 TYPE 的范围发空表。 |
| fields | 发送当前范围全部可指定字段，包括普通关键词默认未勾选的字段。每行保留命令名、中文语义、类型或枚举值。枚举键与显示名不同时给出映射，如 reading 对应“在读”。有范围限制时附上下限。多实体的 text 按所属实体标注“影片影评”“旅途描述”等含义。字段的文本值由用户提供。 |
| modes | 当前页面确实支持的模式和选项，如全文开关。若切换模式会改变可用字段，在对应选项旁列出字段或实体范围；最终按表达式选择的模式校验。没有模式发空表。 |
| today、timezone | 提交当时用户当地的日期和时区。始终发送，免去本地猜测“上个月”“去年”的步骤。 |
| request | 独立对话框里的用户原话。新搜索默认生成完整新式子。 |
| conversation（有前文时） | 当前页面本轮已成功提交的用户描述和模型回复。点「应用」、点「重置」或切换页面后清空。 |

### 字段的可选内容如何填写

只列业务规定的合法选项。自由文本字段可以查询用户库中尚未出现过的词；实际能否命中，由本地搜索决定。

| 类型 | 每次发送的约束 | 例子 |
|---|---|---|
| text | 只发含义和类型。文本值直接取用户原话，保留人名、标题和标签原词。 | “作者是余华”生成 `author:余华`。即使书库没有这位作者，这仍是一条合法查询，执行后为零条。 |
| enum | values 列齐允许值。若显示名与命令值不同，使用“命令值 → 显示名”的映射。 | 阅读状态的 values 为 `{"unread":"待读","reading":"在读","finished":"已读"}`。 |
| bool | 固定说明已定义 YES 和 NO，各字段只发含义和类型。 | “没有海报”生成 `photo:NO`。 |
| number | 发实际存在的 min、max，包含端点。无边界的一端省略。 | “个人评分至少八分”生成 `personalScore:FROM 8`。评分控件的步长 0.1 描述界面输入，当前语句引擎支持小数比较。 |
| date | 固定说明已定义 YYYY-MM-DD 和日历日范围。 | 结合 today 解释“上个月”，不枚举具体日期。 |
| clockText | 固定说明已定义 HH:mm 和文本匹配。 | “上午九点零五分”生成 `time:09:05`。 |

多实体字段的第三项可附 `owners`，例如 `{"owners":{"movie":"影评","journey":"旅途描述"}}` 表示同一个 text 命令在这两个实体上的含义（实际发送时列齐当前范围的适用实体）。用户以“那个标签”“那位作者”指代某个未知名称且上下文无法确定时，用 ask 请求具体名称。

组装时从 `scopeFields` 取得页面字段，用 `fieldCommand` 取实际命令名，用 `typedFields` 和范围控件补上枚举、值类型和边界；从 `filterExpression` 使用的页面配置取得模式。相同的公共字段和枚举表可在同一请求内去重。模板与页面表可以在应用内缓存，普通无状态 API 调用仍须发送它们。每次提交一次请求；打字过程不调用模型。实体记录、书籍正文、照片、搜索结果和水晶球聊天历史均不用于组装请求。

## 完整示例：影片收藏

假设用户当地日期是 2026-11-28。在固定 system 之外，这次 user 消息的全部内容如下。为便于阅读，这里将 JSON 换行；发送时可以紧凑序列化。

```json
{
  "scope":"影片收藏",
  "types":{"movie":"影片"},
  "related":false,
  "fields":{
    "title":["片名","text"],
    "tags":["标签","text"],
    "genres":["影片类型","text"],
    "movie.region":["出品国家或地区","text"],
    "createdAt":["创建日期","date"],
    "movie.status":["观看状态","enum",{"values":["想看","在看","看过"]}],
    "score":["豆瓣评分","number",{"min":0,"max":10}],
    "personalScore":["个人评分","number",{"min":0,"max":10}],
    "watchedOn":["观影日期","date"],
    "text":["影评","text"],
    "url":["影片链接","text"],
    "douban":["豆瓣链接","text"],
    "photo":["有海报图片","bool"]
  },
  "modes":{},
  "today":"2026-11-28",
  "timezone":"Asia/Shanghai",
  "request":"上个月我看过的、自己打了至少八分的电影"
}
```

模型期望回复：

```json
{"query":"movie.status:看过 AND watchedOn:FROM 2026-10-01 TO 2026-10-31 AND personalScore:FROM 8"}
```

如果原话只有“找八分以上的电影”，可返回 `{"ask":"你指豆瓣评分还是你自己的评分？"}`。用户回答“我自己的”，下一次请求使用相同的页面表，把原请求和追问放入 conversation，新 request 填“我自己的”。期望得到 `{"query":"personalScore:FROM 8"}`。如果在记忆点页要求“任意一天早上九点到十点之间拍的照片”，当前 time 字段仅支持文本匹配，应返回 unsupported。

## 本地验收与失败处理

1. 只接受单键 JSON 对象，值须是非空字符串。ask 进入追问，unsupported 显示原因。只有 query 可以进入搜索。
2. 对照提交时的范围，先解析页面模式，再用实际模式的字段表和现有语法解析器验收。核对类型白名单、字段归属、枚举、布尔、合法日历日期、评分边界、范围上下限，以及 RELATED 的可用性。没有开启的运算符不能退化成普通关键词生效。现有评分控件的 0～10 边界需在 AI 结果验收时补查，现有语法检查单独使用还不够。
3. 用户点击「应用」后用完整表达式替换输入框，沿用普通搜索执行并回显右侧筛选。校验失败、请求失败或无法表达时保留原条件；原页面已切换、用户已改写输入、或者较新的请求已提交时，丢弃旧回包。首版不做后台自动重试。
4. 合法只表示当前引擎可以执行。字段理解错误仍可能得到合法表达式，因此将最终式子留在输入框供用户核对和编辑。接入验收应分别覆盖字段选择、歧义追问、无法表达和本地拒绝非法输出。
