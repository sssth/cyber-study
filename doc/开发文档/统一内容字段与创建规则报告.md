# 赛博书房：统一内容字段与创建规则报告

> 本文为历史 v1 讨论稿。已按用户修订更新为同目录《统一内容字段与创建规则报告-v2.md》，冲突内容以 v2 为准。

版本：讨论稿 v1；整理日期：2026-11-16。

## 1. 报告的适用范围和阅读方法

本报告覆盖 12 种内容：书籍、摘录、批注、抄写作品、旅途、记忆点、歌单、歌曲、影片、日记、便签、待办。不包含植物、宠物、画质偏好等运行状态。

**这是下一步统一数据模型的设计报告，不表示这些规则已经实现。** 当前实验室实现了公共字段、自由 JSON 专属字段与关系校验；正式项目仍使用各模块原有保存方式。报告不自动修改实验室或正式项目。

- **已确认**：关系类型及允许组合，见第 3 节。
- **代码现状**：单独列在第 2 节及各类型的“当前情况”。
- **建议规则**：第 4 节以后的字段要求、自动补全、标签、附件、创建流程，均为待审核方案。即使某个字段已存在，其必填规则也不一定已实施。

表中“必填”指保存正式条目时字段有有效值，并不意味着用户必须亲手输入。

| 标记 | 含义 |
|---|---|
| 系统必有 | 系统创建、管理，用户不填写 |
| 必填 | 可手填、导入或由上下文生成，但正式保存时必须有效 |
| 条件必填 | 满足指定情形时才要求 |
| 可选 | 无值允许保存；未知值使用 null 或空数组 |

统一时机：**打开表单 → 提供默认值；选择来源/上传 → 解析并预填；用户确认 → 校验；保存成功 → 正式创建条目与关系；后续编辑 → 更新相关字段。** 表单预览不能直接等同于已持久保存。

## 2. 当前实验室实际有哪些字段

### 2.1 公共字段现状

`id, type, title, summary, createdAt, updatedAt, occurredAt, deletedAt, tags, coverAssetId, schemaVersion, data`。

当前保存表单要求标题非空、data 为有效 JSON 对象；ID、类型、创建及更新时间由程序生成；标签只按用户输入的逗号拆分。**目前没有地点自动打标签、平台元数据自动填充或专属字段逐项校验。** 发生时间可以为空；附件只有引用字段，没有真实上传。

### 2.2 专属模板现状

| 类型 | 当前实验室 data 模板 |
|---|---|
| book | author, source, assetId |
| excerpt | quote, bookId, position, starred, annotations |
| annotation | text |
| typing_work | text, textId, complete |
| journey | description, startDate, endDate, location |
| memory_point | country, region, city, latitude, longitude, caption, visitStatus |
| playlist | description |
| music | artist, provider, sourceId, url |
| movie | url, status, score, douban |
| diary | text, mood, location |
| memo | text, tone |
| todo | text, done |

用户可在 JSON 中增加字段，因此实际条目不一定只含模板字段。本报告核查的是代码定义，**没有读取用户当前浏览器里自建条目的实际数据**。

## 3. 已确认的关系约束

| 关系 | 允许的类型组合 | 数量 |
|---|---|---|
| 直属 direct | 书籍→摘录、书籍→抄写作品、摘录→批注 | 子项最多一个直属上级；父项可有多个下级 |
| 包含 contains | 旅途→记忆点、歌单→歌曲 | 两侧都可多个 |
| 关联 related | 除以上保留组合外的不同类型组合 | 可多个；双向查询 |

同类型不关联、自身不连接、重复连接禁止；上下级联合检查循环。关系独立存储，不把父子 ID 数组重复写进每类 data。

**新增建议（尚未确认）**：正式摘录、批注、抄写作品保存时要求选定直属来源；草稿可暂缺。实验室目前仅限制“最多一个”，允许没有直属上级。可先保留这个宽松行为，待新建流程确认后再收紧。

来源 ID 的权威值来自 direct 关系。展示时可计算 `parentId`，不同时维护可独立编辑的 `data.bookId` 与直属关系。原文定位是另外的数据，必须保留，不由关系替代。

## 4. 所有类型共同拥有的字段

| 字段 | 类型 | 要求 | 何时生成或更新 | 用户控制 |
|---|---|---|---|---|
| id | UUID string | 系统必有 | 首次持久保存分配；重复提交复用同一创建请求，不产生两条 | 不可修改 |
| type | enum string | 系统必有 | 由新建入口或所选类型确定 | 保存前可选；保存后不直接改类型 |
| title | string | 必填 | 用户输入；或按第 6 节兜底生成 | 可修改；建议 1–200 字符 |
| summary | string/null | 可选 | 用户填写；没有时列表可从正文截取预览，但不把预览写成事实摘要 | 可修改 |
| createdAt | ISO datetime | 系统必有 | 首次保存成功记录，之后不变 | 不可修改 |
| updatedAt | ISO datetime | 系统必有 | 内容/内容元数据修改时更新 | 不可修改；拖动图谱不更新 |
| occurredAt | ISO datetime/null | 可选 | 已知实际发生时刻时填入，区别于上传时间 | 可修改；不知道时不填当前时间冒充 |
| deletedAt | ISO datetime/null | 系统必有 | 默认 null；进入回收站记录时间，恢复置 null | 通过删除/恢复操作修改 |
| tags | string[] | 系统必有，可为空 | 用户标签与已确认的自动标签合并去重 | 手工增删；详见第 5 节 |
| coverAssetId | UUID/null | 可选 | 上传并选择封面时生成；必须引用有效图片附件 | 可替换、清空 |
| schemaVersion | integer | 系统必有 | 当前格式版本；数据迁移成功后递增 | 不可编辑 |
| data | object | 系统必有 | 按类型初始化、校验、保存 | 通过类型表单编辑 |

### 4.1 建议增加的公共辅助字段

| 字段 | 类型 | 要求 | 用途和生成时机 |
|---|---|---|---|
| recordState | draft / active | 系统必有，新增建议 | 自动保存草稿时 draft；满足正式校验后 active。仅描述完整度，不替代 done/complete/visitStatus |
| tagOrigins | object[] | 系统必有，可空，新增建议 | 每条自动标签记录来源字段和标准标识；字段变化时精准替换旧标签 |
| suppressedAutoTags | string[] | 系统必有，可空，新增建议 | 用户关闭某个自动标签时记录，防止下次保存又出现 |
| fieldSources | object map | 可选，新增建议 | 对自动解析字段记录来源与用户是否覆写，例如 EXIF、平台、用户；不必给所有手工字段都建记录 |
| creation | object | 系统必有，新增建议 | `{method, batchId?, originalName?}`，保存本次创建来自手工、文件、平台或上下文入口 |

`creation.method` 建议值：manual、file_import、platform_import、selection、context、derived。字段来源用内部结构记录；不把“手工创建”“来自EXIF”作为默认用户标签。

时间：存储绝对时刻用 ISO 8601 带时区，界面按用户时区显示。只有日期时存专属 date 字段，不虚构午夜时刻。EXIF 无时区时保留本地日期/时间，occurredAt 可为空；用户指定时区后才转换。

## 5. 自动标签与自动填充：统一规则

### 5.1 标签范围

建议自动标签只来自确定、可解释的字段：**已确认地点、作者/艺术家、明确分类、用户明确选定的心情**。标签带来源记录，显示短名称，内部可用稳定标识去重，例如杭州城市编码。

不默认自动生成：ID、文件格式、创建方式、所有正文关键词、每一级日期、内容类型、完成状态。类型和状态本来可筛选，不需要再复制成标签。不会默认调用 AI 理解私人正文；智能建议若以后增加，应让用户确认。

### 5.2 触发与更新

| 用户动作/事件 | 自动动作 | 不自动做的事 |
|---|---|---|
| 明确选择杭州某地点并保存 | 填标准地点字段；生成“杭州”等地点标签 | 不从模糊输入“杭州附近”猜精确坐标 |
| 仅导入有 GPS 的照片 | 记录 EXIF 坐标与来源；可提供待确认地点候选 | 不把 GPS 直接当成用户确认的地点 |
| 用户确认地点候选 | 标为 confirmed，并生成地点标签 | 不修改其他关联条目的地点 |
| 输入明确作者/艺术家 | 保存后生成对应人物标签 | 不猜作者性别、籍贯等 |
| 选择影片类型/手工标签 | 去重加入对应标签 | 不把网页全部关键词照搬 |
| 修改自动标签来源字段 | 替换该字段产生的自动标签 | 不删除用户手工添加的同名标签 |
| 手工删除自动标签 | 记住禁止自动恢复的选择 | 不在下次保存时悄悄加回来 |
| 建立或解除关系 | 更新“关联地点”等查询结果 | 不把对方标签复制进自身 tags |

合并规则：首尾去空白、Unicode 规范化、完全相同的标签去重；地点同义词依稳定地点 ID 合并，其他词不随意认定同义。一个标签同时来自用户和自动规则时保留两种来源。

推荐优先级：**本次用户明确输入 > 用户已确认的历史值 > 可信来源的新解析值 > 默认值**。平台刷新、重导入或重新解析不覆盖用户修改；冲突展示对比后决定。

例：记忆点从杭州改为苏州，系统仅替换“由地点字段产生的杭州标签”。若用户也手工添加过“杭州”，该手工标签继续保留；关联到此点的日记不跟着改 tags。

## 6. 各类型的标题和标签默认策略

| 类型 | 未填写标题时的建议 | 可以自动生成的标签 | 默认不生成 |
|---|---|---|---|
| 书籍 | 来源元数据标题 → 正文主标题 → 去扩展名的文件名 | 作者、明确分类（有可靠来源时） | “书籍”“PDF” |
| 摘录 | 摘录前 24 字截断作为标题 | 默认无；出处通过直属查询 | 自动复制整本书全部标签 |
| 批注 | 批注前 24 字 | 默认无 | 自动复制摘录标签 |
| 抄写作品 | “抄写·章节名”或“抄写·书名” | 默认无 | “已完成”“未完成” |
| 旅途 | 建议用户填写；不按未知地点乱生成 | 用户确认的目的地城市 | 子记忆点全部地点自动变成自身标签 |
| 记忆点 | 地点名＋已有日期 → 照片文件名 → “未命名记忆点” | 确认地点的国家/省区/城市；详细地点名称可选 | 从坐标猜旅行主题 |
| 歌单 | 来源歌单名；手工创建要求填写 | 来源有明确分类时提供候选 | 全部歌曲歌手的并集 |
| 歌曲 | 平台/音频元数据标题 → 音频文件名 | 艺术家；genre 有明确值时可选 | “缓存成功”“平台登录” |
| 影片 | 豆瓣等来源标题 → 用户标题 | 国家/地区、影片类型；导演后续有字段才考虑 | “想看”“在看”“看过” |
| 日记 | “日期＋日记”；日期缺失时“未命名日记” | 用户确认地点、用户主动选择心情 | 默认为平静就自动生成心情标签 |
| 便签 | 正文前 24 字；图片便签为图片名 | 默认无 | 便签颜色 |
| 待办 | 待办事项本身作为标题 | 默认无 | “未完成”“已完成” |

前 24 字按用户可见字符截断。自动标题只在初次缺省时生成，之后修改正文不覆盖用户标题。正文预览可以实时变化。

## 7. 书籍 book

**当前情况**：正式项目支持本地书籍导入及文件夹导入；书籍正文与元数据分开存储。实验室只有 author、source、assetId。

**建议创建方式**：①单本文件上传；②多文件/文件夹批量导入；③手工建书籍资料卡，之后补文件。资料卡没有正文时，不能执行原文选区摘录；可手工补录有来源的摘录但明确定位不完整。

| 专属字段 | 类型 | 要求 | 何时创建 / 默认 / 校验 |
|---|---|---|---|
| author | string/null | 可选 | 文件元数据或正文作者行解析；无值不使用“本地导入”冒充作者 |
| source | string/null | 可选 | 来源网址/用户来源说明；上传来源记录在 creation，二者含义分开 |
| isbn | string/null | 可选，新增建议 | 元数据或手填；格式校验，不强制网络查询 |
| description | string/null | 可选，新增建议 | 手填或来源简介；未获取不生成事实描述 |
| originalAssetId | UUID/null | 文件导入时必填，新增建议 | 文件写入成功后关联原件 |
| readingAssetId | UUID/null | 可阅读时必填，新增建议 | 转换正文成功后写入；原件与阅读件可为不同附件 |
| format | enum/null | 有阅读文件时必填，新增建议 | 从实际文件/转换产物确定，不只信扩展名 |
| parseStatus | pending/ready/failed/metadata_only | 系统必有，新增建议 | 解析阶段更新；失败保留原件并允许重试 |
| contentRevision | integer/null | 有可定位正文时必填，新增建议 | 首次解析 1；正文内容变更时更新，用于定位版本匹配 |

保存最低条件：标题有效。文件导入成功需至少原件成功落盘；解析失败可以留下明确失败状态的资料卡，不伪装为已可阅读。

标题、作者解析发生在文件读取后；封面来自真实封面附件或用户上传。附件 hash 用于重复检测；相同文件建议提示复用，不依标题去重。自动标签见第 6 节。

## 8. 摘录 excerpt

**当前情况**：正式项目通过阅读器选区创建笔记，原文、批注、书籍 ID、定位常在同一 note 中；实验室保留 quote/bookId/position/starred/annotations 旧模板，同时有独立批注类型。统一方案应逐步拆分批注，不能直接丢弃旧数组。

**建议创建方式**：①阅读器选中文字创建；②书籍详情里手工录入摘录；③导入结构化摘录并确认对应书籍。正式保存建议要求直属书籍；手工摘录可以没有精确定位。

| 专属字段 | 类型 | 要求 | 何时创建 / 默认 / 校验 |
|---|---|---|---|
| quote | string | 必填 | 选区自动填原文，或手工输入；不得仅空白 |
| position | Position/null | 选区创建时必填；手工录入可空 | 保存原文精确范围，见第 20 节 |
| starred | boolean | 系统必有 | 默认 false；加星操作修改 |
| sourceTitleSnapshot | string/null | 可选，新增建议 | 创建时记录书名副本，来源书移除后仍可识别出处 |
| locationState | exact/unlocated/stale | 系统必有，新增建议 | 选区 exact；手工无定位 unlocated；正文版本变化无法匹配时 stale |

直属书籍在关系层保存。旧 `data.bookId` 迁移后不作为第二个可编辑来源；旧 `annotations[]` 逐条转换为批注条目及直属关系，并保留迁移映射。选区与用户手填内容冲突时，不再声称可精确高亮原文。

批量导入建议按“书籍＋正文版本＋范围＋原文”识别重复候选；让用户选择合并，不仅凭摘录文字全局去重。标签默认手工，不自动复制书籍标签。

## 9. 批注 annotation

**当前情况**：实验室有独立 annotation，字段 text；正式项目批注仍主要在笔记记录里。

**建议创建方式**：①在摘录下点击新增批注；②全局新建后选择直属摘录；③从旧批注数据迁移。保存正式批注建议要求直属摘录。

| 专属字段 | 类型 | 要求 | 何时创建 / 默认 / 校验 |
|---|---|---|---|
| text | string | 必填 | 用户书写，或迁移原批注；纯空白不能正式保存 |

最低模型只需要正文，不把摘录全文、书名、页码复制到批注。来源和原文位置沿批注→摘录→书籍查询。标题可从正文生成，标签由用户填。允许一条摘录下多条批注；不因文字相同就自动合并。

## 10. 抄写作品 typing_work

**当前情况**：正式项目从内置文本开始抄写，textId 指内置文本；实验室 textId 含义未规范。已确认新的直属关系是书籍→抄写作品，现有内置文本需要先匹配/创建来源书籍，不能直接当作书籍 ID。

**建议创建方式**：①书籍内选择一段原文后开始抄写；②新建作品时选择书籍与目标片段；③从已有摘录开始，沿其直属关系找到书籍，作品仍直属书籍；④旧作品迁移后补来源。

| 专属字段 | 类型 | 要求 | 何时创建 / 默认 / 校验 |
|---|---|---|---|
| text | string | 系统必有；正式作品至少非空 | 初始空；输入时存草稿，保留用户真实输入 |
| targetText | string | 开始正式抄写时必填，新增建议 | 选择来源时保存目标原文快照 |
| position | Position/null | 有精确原文选区时必填，新增建议 | 创建时记录来源书内位置；手工来源允许无定位 |
| sourceTextId | string/null | 可选，新增建议 | 仅保留内置练习文本/导入源的稳定标识，不替代书籍关系 |
| complete | boolean | 系统必有 | 按匹配规则计算；默认 false，不手填 |
| completedAt | ISO datetime/null | 可选，新增建议 | 首次完成当前目标时写入；再次编辑为未完成时清空 |
| renderAssetId | UUID/null | 可选，新增建议 | 用户生成作品图片成功后写入 |

建议首版沿用精确字符匹配判断 complete；忽略空格/标点若以后开放，需保存所用匹配规则版本。目标文字更换需要明确确认，不静默重置作品。创建时间不随每次保存重写。生成图片是快照，正文变化后旧图片不自动同步。

## 11. 旅途 journey

**当前情况**：正式项目旅途有 title、note、pointIds；实验室有 description、startDate、endDate、location。统一后 note 映射 description，pointIds 转 contains 关系。

**建议创建方式**：①手工新建空旅途；②从已选记忆点创建旅途；③批量照片导入后由用户确认建立旅途。第三种是新增流程建议，不自动把一个文件夹认定为一次旅行。

| 专属字段 | 类型 | 要求 | 何时创建 / 默认 / 校验 |
|---|---|---|---|
| description | string/null | 可选 | 新建或编辑时填写 |
| startDate | YYYY-MM-DD/null | 可选 | 用户填写；从所选点的最早日期生成候选后确认 |
| endDate | YYYY-MM-DD/null | 可选 | 同上，取最晚日期候选；两者存在时不得早于开始日期 |
| destinations | Location[] | 可选，默认 []，新增建议 | 用户选一个或多个目的地；替代只有一个 location 文本的限制 |

标题建议手填；空旅途合法。包含关系在用户选择点并保存时创建。点的数量、已到访数量、覆盖城市应计算，不存多个容易失配的计数字段。增删记忆点不自动改用户填写的旅途日期/目的地，可展示“实际点位范围”供参考。

标签只来自用户确认目的地，不从所有子点递归复制。跨城市旅途不强行生成一个中心坐标。

## 12. 记忆点 memory_point

**当前情况**：正式项目可手工保存点、选择多张照片、递归导入文件夹；导入会读取 EXIF 日期/GPS，照片最多 80 MB，按 hash 检查重复。当前一个记忆点最多一张照片。文件选择器允许部分格式，但能否解码仍依运行环境；不能承诺所有 HEIC 均成功。

**建议创建方式**：①地图选点后填写；②纯文字/地点手工创建；③单张照片导入；④多张照片或文件夹批量导入；⑤在旅途内新增；⑥选择多张照片合成一个点（新增建议，需要多附件支持）。

| 专属字段 | 类型 | 要求 | 何时创建 / 默认 / 校验 |
|---|---|---|---|
| country、region、city | string | 可选 | 国家、省区和城市 |
| country / region / city | string/null | 可选 | 地点选择器解析并确认后生成 |
| placeId / cityId | string/null | 可选 | 标准地点库有标识时存；自由文本不伪造 ID |
| latitude / longitude | number/null | 有坐标时成对必填 | 地图选择、EXIF 或手填；纬度 -90..90、经度 -180..180；0 是有效值 |
| caption | string/null | 可选 | 用户记录文字 |
| date | YYYY-MM-DD/null | 可选 | EXIF 拍摄日期或手填；不拿导入日期代替 |
| time | HH:mm[:ss]/null | 可选 | EXIF 或手填；没有时不补 00:00 |
| timezone | string/null | 可选，新增建议 | 已知拍摄时区时保存；与 date/time 共同转换 occurredAt |
| visitStatus | visited/wish/unknown | 系统必有 | 手工选择；建议照片导入默认 unknown 待确认，区别于当前偏向 visited 的行为 |
| locationStatus | pending/confirmed | 系统必有 | 原始 EXIF 为 pending；用户确认或明确地图选点为 confirmed |
| locationSource | manual/map/exif/city-center/unknown | 系统必有 | 从本次赋值方式生成，不由位置值猜测 |
| dateSource | user/exif/unknown | 系统必有 | 从赋值方式生成 |

正式保存至少有：有效地点信息、非空文字、成功保存的照片三者之一。坐标不是必填，纯文字记忆点合法；只有标题不算有记忆内容。封面默认第一张成功附件，可调整。

### 12.1 批量照片导入的字段生成顺序

1. 用户选择照片/文件夹，建立批次 ID；此时不创建空记忆点。
2. 逐文件检查可读、大小、格式、hash；相同照片提示复用或跳过，回收站中的重复项提示恢复。
3. 解码并保存原图、缩略图；失败返回该文件的具体原因，不生成假成功条目。
4. 读取 EXIF。获得日期/GPS就记录值及来源，没有则留空；不生成虚构经纬度。
5. 默认一张照片产生一个记忆点，标题从文件名兜底；地点名、到访状态待确认。若希望多张合一，先预览分组，用户确认，不按时间相近直接合并。
6. 用户确认地点后更新结构化地点与 locationStatus，生成地点标签。只存在原始 GPS 时不自动生成确定地点标签。
7. 从旅途入口导入时，成功条目自动建立该旅途的 contains 关系；失败文件不建立连接。
8. 显示成功、重复跳过、失败列表；重试只处理失败项，不再次生成已成功条目。

原始文件名、路径、hash 建议放附件或导入记录，记忆点只保留附件引用。经纬度属于自身地点，不继承所属旅途的目的地。

## 13. 歌单 playlist

**当前情况**：正式项目歌单成员关系嵌在歌曲 playlists 中；实验室已有独立歌单，但只有 description。完整歌单主记录是统一方案的新增部分。

**建议创建方式**：①手工建空歌单；②选择已有歌曲建歌单；③导入平台歌单。

| 专属字段 | 类型 | 要求 | 何时创建 / 默认 / 校验 |
|---|---|---|---|
| description | string/null | 可选 | 手填或来源歌单简介 |
| provider | enum/null | 平台导入时必填，新增建议 | 从导入入口确定平台 |
| sourceId | string/null | 平台导入时必填，新增建议 | 解析平台歌单 ID |
| sourceUrl | URL/null | 可选，新增建议 | 合法来源链接；不保存凭据 |
| lastImportedAt | ISO datetime/null | 平台导入成功时必填，新增建议 | 记录最近成功导入时刻，不等于 createdAt |

标题必填/可从平台生成；空歌单合法。成员与顺序保存在 contains.position，不再嵌入每首歌重复保存歌单标题。重复导入同平台歌单按 provider+sourceId 匹配，建议增量合并，不自动删除用户手工加入的歌曲。封面可由平台真实图片或用户指定，不递归收集所有歌曲标签。

## 14. 歌曲 music

**建议创建方式**：①平台歌单导入；②单曲链接/ID导入；③单个/多个本地音频文件导入；④手工记录音乐资料卡。单曲入口、资料卡入口是否全部开放仍需产品确认。

| 专属字段 | 类型 | 要求 | 何时创建 / 默认 / 校验 |
|---|---|---|---|
| artist | string/null | 可选 | 平台/音频元数据/手填；多人时建议后续升级结构化数组 |
| album | string/null | 可选，新增建议 | 平台或音频元数据 |
| genre | string[] | 可选，新增建议 | 明确元数据或用户选择；可生成标签 |
| provider | enum/null | 平台创建时必填 | 入口确定；本地音频不冒充平台 |

资料卡可以无可播放源，但必须显示“仅资料，暂无音源”。缓存是否可用、播放进度、授权状态单独管理，不要求用户填写，也不用于生成内容标签。同平台同 sourceId 建议复用现有歌曲，再添加歌单包含关系；同标题不自动合并。

## 16. 日记 diary

**当前情况**：正式项目记录 text、mood、photo、date；图片为内嵌 Data URL。实验室 text/mood/location。统一附件及多图片是新增方案。

**建议创建方式**：①日记本手工写；②日历选一天新建；③从记忆点/旅途等入口“写日记并关联”；④由抄写作品生成图片后加入新日记。

| 专属字段 | 类型 | 要求 | 何时创建 / 默认 / 校验 |
|---|---|---|---|
| text | string | 可选，但与附件至少有一项 | 用户书写；图片日记可无正文 |
| date | YYYY-MM-DD | 必填，新增到实验室的建议 | 打开日记表单默认本地当天，可改为过去日期 |
| mood | enum/string/null | 可选 | 建议默认为未选择；用户选择后才生成心情标签 |
| location | Location/null | 可选 | 用户明确填写自身发生地点；不从关联点复制 |

日期必填不代表精确时刻已知，只有 date 时 occurredAt 可空。日记标题可日期兜底。上下文创建时自动添加合法 related 关系；用户可看见并取消预选关系。日记不包含记忆点或歌曲，按已确认规则统一关联。旧 photo 转附件关联，原 date 若是创建时间需保留来源，不假设必然是内容发生时间。

## 17. 便签 memo

**当前情况**：正式项目 memo 数组混合文字、图片与 todo；实验室已经拆出 todo，但 memo 仅 text/tone。图谱坐标不是便签内容属性。

**建议创建方式**：①手工文字便签；②上传图片生成便签；③粘贴文字/图片；④抄写作品生成图片后放入便签。粘贴路径与统一附件保存是新增建议。

| 专属字段 | 类型 | 要求 | 何时创建 / 默认 / 校验 |
|---|---|---|---|
| text | string | 条件必填 | 没有图片附件时必填；默认空 |
| tone | enum | 系统必有 | 默认 blue，限受支持颜色；只是外观，不自动标签 |
| kind | text/image/mixed | 系统必有，新增建议 | 按正文及附件组成计算，不让用户输入矛盾状态 |

保存必须有正文或成功附件；图片便签可自动以文件名作标题。位置、宽高放布局数据，不放公共字段，也不因移动便签修改正文时间。便签引用歌曲/记忆点等统一建立 related，不建立 contains。

## 18. 待办 todo

**当前情况**：正式项目待办在 memo 内，核心字段 text/done；实验室独立 todo。

**建议创建方式**：①快速输入事项；②从日记/记忆点/书籍等入口“为此创建待办并关联”；③多行文本分拆为多条待办，先预览确认（新增建议）。

| 专属字段 | 类型 | 要求 | 何时创建 / 默认 / 校验 |
|---|---|---|---|
| text | string | 必填（兼容期） | 当前存事项正文；建议正式模型改由 title 保存事项，避免双份编辑 |
| description | string/null | 可选，新增建议 | 补充说明，区别于事项标题 |
| done | boolean | 系统必有 | 默认 false，勾选更新 |
| completedAt | ISO datetime/null | 系统管理，新增建议 | 勾选完成时填，撤销完成时清空 |
| dueDate | YYYY-MM-DD/null | 可选，新增建议 | 用户指定截止日期，默认无 |
| dueAt | ISO datetime/null | 可选，新增建议 | 只有用户指定具体截止时刻与时区时填写；与 dueDate 保持一致 |

建议新模型采用 title 作为唯一事项名称，旧 text 迁移到 title，避免 title 和 text 内容长期不一致。dueDate 是计划截止时间，不能填入 occurredAt 冒充发生时间。用户一次关联多个记忆点是合法的；完成待办不删除关联。第一版无子待办包含、无 todo↔todo 关联。

## 19. 附件统一规则（跨类型）

所有附件字段均为新增统一模型建议；现有模块并未全部采用。

| 附件字段 | 类型 | 要求 | 创建时机 |
|---|---|---|---|
| id | UUID | 系统必有 | 附件成功写入时 |
| storageKey | string | 系统必有 | 保存后的相对存储位置，不固定绝对机器路径 |
| originalName | string/null | 可选 | 从上传文件名获取；生成图片可用生成名称 |
| mimeType | string | 系统必有 | 实际内容验证后确定 |
| size | integer | 系统必有 | 原始文件字节数 |
| sha256 | string | 系统必有 | 文件内容校验/去重 |
| createdAt | ISO datetime | 系统必有 | 写入成功时 |
| width / height | number/null | 图片可选 | 解码后产生 |
| durationSeconds | number/null | 音视频可选 | 解析后产生 |
| sourceUrl | URL/null | 可选 | 来源下载地址；不保存登录凭据 |

条目附件关联：`{id, itemId, assetId, role, position, caption}`。itemId、assetId、role 必填；position 系统默认顺序；caption 可空。role 建议为 cover/photo/audio/original/reading/render。

coverAssetId 必须指向此条目已关联的有效图片。照片附件可被多个条目引用；原图 hash 相同不重复保存文件，但不强制把两个内容条目合并。移除附件关联，不立即删除仍被其他条目使用的文件。首版不要上传完就自动删除本机原文件。

## 20. 原文定位和字段结构

### 20.1 Position（摘录、抄写作品）

| 字段 | 类型 | 要求 | 说明 |
|---|---|---|---|
| contentRevision | integer | 精确定位必填 | 匹配阅读正文版本 |
| ranges | object[] | 精确文字选区必填 | 每项 `{blockId:string,start:integer,end:integer}`，start>=0，end>start，且在块内 |
| chapterId | string/null | 可选 | 章节跳转提示 |
| page | integer/null | 可选 | 只用于有稳定原始页码的来源，不能把随字号变化的页面当固定页码 |
| quoteSnapshot | string/null | 可选 | 校验/尝试重新定位，不能保证唯一匹配 |

归属书籍从 direct 查询，不在 Position 内再维护独立 bookId。批注沿直属链拿到摘录 Position。定位失效时显示摘录并提示无法精确跳转，不跳到猜测的位置冒充成功。

### 20.2 Location（旅途目的地、日记自身地点及记忆点结构化迁移）

`{label, placeId?, country?, region?, city?, latitude?, longitude?, precision?, source?, confirmed}`。

label 为显示名；坐标成对可空；precision 可取 place/city/region。city-center 坐标不是照片精确拍摄位置，界面要说明。当前记忆点仍用扁平字段，迁移时选一种权威结构，不长期双写两套。

### 20.3 标签来源例子

```json
{
  "tags": ["杭州", "旅行"],
  "tagOrigins": [
    {"tag": "杭州", "kind": "field", "field": "data.cityId", "sourceId": "city-hangzhou"},
    {"tag": "旅行", "kind": "user"}
  ],
  "suppressedAutoTags": []
}
```

这是结构示例，city-hangzhou 只是说明性标识，不是已选定地理数据库的真实编码。

## 21. 每种创建入口何时产生关系

| 入口 | 保存时创建的关系 | 是否复制对方字段/标签 |
|---|---|---|
| 从书籍划线生成摘录 | 书籍→摘录 direct | 原文及定位作为摘录内容；不复制所有标签 |
| 在摘录下写批注 | 摘录→批注 direct | 不复制摘录原文到批注正文 |
| 从书籍/摘录开始抄写 | 来源书籍→作品 direct | 保存目标文字/定位快照；从摘录入口可另建立合法关联，需明确呈现 |
| 在旅途中新增记忆点 | 旅途→记忆点 contains | 不把旅途目的地当作点的精确坐标 |
| 在歌单中导入歌曲 | 歌单→歌曲 contains | 不把歌单标签全部复制给歌曲 |
| 从记忆点新建日记/待办 | 两者 related | 不自动写入日记地点或待办标签 |
| 从任意条目新建跨类型内容 | 仅当类型组合允许时建立相应关系 | 关系不传染字段；新建面板明确显示连接方向 |
| 全局新建 | 默认没有关系 | 用户选来源/集合后才产生关系 |

创建来源上下文不等于可以绕过类型规则：从日记入口不能再关联另一篇日记；从歌曲入口创建歌单应使用 contains，而非 related。

条目、必需附件引用和用户确认的关系建议在同一次提交中一致保存。可重试操作用同一个 requestId，重试不能重复新增。保存失败保留表单，显示未保存；部分批量成功逐条反馈。

## 22. 状态、异常与完整性

| 场景 | 建议行为 |
|---|---|
| 解析不到元数据 | 使用允许的标题兜底；未知作者/日期/位置留空 |
| 网络解析失败 | 保留用户链接和输入，允许重试或手工补全；不伪造评分、歌手 |
| 附件上传失败 | 不创建悬空附件引用；文字内容可按该类型最低条件另行保存 |
| 用户修正自动填值 | 标记用户覆写，后续解析不覆盖 |
| 撤销/取消创建 | 不留下正式空条目；已临时上传资源后续清理 |
| 重复平台导入 | 同 provider+sourceId 复用条目；只补缺关系与未被手改的元数据 |
| 原文更新 | 检查定位版本，无法重定位标 stale；保留摘录快照 |
| 删除直属上级 | 需要单独定义保留/回收策略；不能自动永久删除所有后代。本报告不替用户决定 |
| 解除集合包含 | 只删关系，内容及其附件保留 |
| 标签来源变化 | 仅调整对应自动来源，手工来源保留 |
| 恢复旧数据 | 检查 schemaVersion、引用、字段类型，保留迁移前备份 |

最大长度、文件容量、每类型附件数量需要实现前统一配置。正式项目现有 80 MB 地球仪照片、2 MB 日记/便签选图等是现状，不自动当作新统一附件库的永久限制。

## 23. 当前字段到建议模型的迁移对照

| 当前字段/结构 | 建议去向 | 避免的问题 |
|---|---|---|
| book.assetId | originalAssetId / readingAssetId + 附件引用 | 不混淆原件与阅读正文 |
| excerpt.bookId | direct 关系 | 不与直属归属冲突 |
| excerpt.annotations[] / note.annotation | annotation 条目 + direct 关系 | 原批注保留，建立迁移 ID 对照 |
| typing_work.textId | sourceTextId 或结构化定位；另建书籍直属 | 不把内置练习 ID 当书籍 ID |
| journey.pointIds | contains 关系及 position | 一个点可在多个旅途中 |
| music.playlists[] | playlist 条目 + contains 关系 | 支持空歌单、统一标题和顺序 |
| diary.photo / memo.photo | 附件与条目附件关联 | 避免大图编码塞进元数据 |
| movie.poster | coverAssetId + 附件来源 | 统一海报和封面管理 |
| movie.score string | number/null | 区分无评分与 0 分 |
| memo 中 todo | 独立 todo 条目 | 文本便签与待办状态分开 |
| 图谱/便签坐标 | layout | 拖动不修改内容正文和内容时间 |

## 24. 建议按这个顺序审核与落实

1. 先确认每类“最低保存条件”：尤其纯资料书籍/歌曲/影片是否允许，独立草稿是否需要。
2. 确认摘录、批注、抄写正式保存是否必须有直属来源，还是继续允许未归属条目。
3. 确认自动标签范围：地点、作者/艺术家、影片分类、用户选择的心情；允许逐条关闭。
4. 确认批量照片默认一图一点，是否第一版支持多图一点；确认导入照片的到访状态是否默认 unknown。
5. 把实验室的自由 JSON 表单逐步换成按类型生成的字段表单，清楚标明“必填、可选、自动生成”。
6. 再模拟上传与解析结果、标签预览、上下文创建和失败情况，审核完成后才接正式项目。
