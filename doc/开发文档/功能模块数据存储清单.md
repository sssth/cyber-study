# 赛博书房功能模块数据存储清单

整理日期：2026-11-16。依据当前 src 与 electron 实现静态核查；描述代码实际写入格式，未读取私人数据、未修改业务代码。可选字段指某些创建路径不写入，并不表示已有完整的数据库约束。

## 1. 整体如何保存

目前没有统一业务数据库或统一数据块模型。持久化分为文件和 localStorage 两套；旧书库另有 IndexedDB 迁移入口。未见云端用户数据同步实现。

开发版文件根目录为项目 `.user-data/`；打包版为 Electron `userData`（macOS 的 Application Support 下应用目录），不能把开发路径写死用于正式版。

下表中的 `space.X` 都是 localStorage 的完整键 `cyber-study.space.v1.X`，其值是 JSON 字符串。localStorage 由 Electron 浏览器存储管理，并非每个键都有独立 JSON 文件。

| 功能 | 保存单元 / 顶层格式 | 位置 |
|---|---|---|
| 书库 | 每本书一个目录，元数据对象、正文、原文件分开 | `books/<书籍ID的SHA256>/` |
| 阅读器 | 设置对象 + 按 bookId 索引的进度对象 | `cyber-study.reader.v1` |
| 知识库 / 书桌 | `{notes: [], projects: []}` | `space.knowledge` |
| 地球仪 | `{version:2, photos:[], migrations:[], journeys?:[]}` + 图片文件 | `memory-globe/library.json`、`memory-globe/assets/` |
| 唱片机 | 歌曲数组，歌单成员关系嵌在歌曲中 | `space.music` + `music-cache/` |
| 影碟机 / 影像收藏 | 影片数组 + 海报文件 | `space.movies` + `movie-posters/` |
| 日记 | 日记数组 | `space.diary` |
| 便签板 | 待办、便签、图片混合数组 | `space.memo` |
| 打字机 | 抄写作品数组 | `space.typewriter` |
| 植物 | 单个养护状态对象 | `space.plant` |
| 宠物 | 单个互动状态对象 | `space.pet` |

文件保存：书籍元数据和地球仪清单采用临时文件写入再重命名。localStorage 保存：通常读出整个数组/对象，修改后整体覆盖，没有跨模块事务。字符串型 ID 普遍由时间戳和随机串生成；地球仪用 UUID；平台歌曲用平台名和来源 ID 组合。

## 2. 数据之间的关系

- 书籍 `book.id` → 阅读进度 `books[bookId]`，以及知识库笔记 `note.bookId`。笔记还保存书名和摘录副本，找不到原书时仍可显示摘录。
- 旅程 `pointIds[]` → 同一个清单中的 `photos[].id`。记忆点单独存储；不要求先属于旅程，代码也不限制一个点只能属于一个旅程，因此存储层支持多对多。
- 记忆点 `hash` → 图片资源的文件名；原图、预览图、缩略图共用这个 hash。一个点当前只有一个 hash，最多关联一张照片。
- 歌曲 `playlists[]` → 该歌曲所属歌单及歌单内排序。没有独立持久化的歌单主表；同一歌曲可以属于多个歌单。
- 打字机作品转到日记/便签时生成图片并创建新记录，没有保存源作品 ID，也不会联动更新。
- 日记每日汇总读取当天日记、知识库笔记和未完成待办数量；汇总本身仅在界面状态中，不作为独立数据保存。
- 阅读专注时长影响植物养护数据。书桌和知识库共用同一功能，不是两套数据。

## 3. 地球仪（旅程与记忆点）

实际字段名仍为 `photos`，但已经承担“记忆点”含义，可保存没有照片的点。

### 旅程 Journey

| 字段 | 类型 | 含义 / 规则 |
|---|---|---|
| id | string | UUID；编辑保留 |
| title | string | 旅程名称；去首尾空格，必填，上限 200 字符 |
| note | string | 旅程说明；可为空，上限 10000 字符 |
| pointIds | string[] | 关联记忆点 ID；保存去重，必须引用清单内已有点 |

目前旅程没有封面、起止日期、创建/修改时间字段。删除旅程只移除旅程记录，不删除记忆点。

### 记忆点 MemoryPoint

| 字段 | 类型 | 含义 / 来源 |
|---|---|---|
| id | string | UUID |
| hash | string/null | 照片 SHA256；没有照片为 null |
| caption | string | 用户记录文字 |
| date | string | 日期；手工保存点路径未做与批量更新路径同等严格的日期校验 |
| time | string，可选 | 时间，手工创建点写入；照片导入路径不一定有 |
| country / region / city | string，可选 | 国家、地区、城市 |
| cityId | string，可选 | 城市标识 |
| latitude / longitude | number/null | 纬度 -90～90，经度 -180～180；缺失为 null |
| visitStatus | string，可选 | `visited` 到过、`wish` 想去；手工保存点要求此字段 |
| locationStatus | string | `pending` 待确认 / `confirmed` 已确认；确认需合法坐标 |
| locationSource | string | `unknown`、`exif`、`city-center`、`manual`，依创建路径 |
| dateSource | string | `unknown`、`exif`、`user` |
| createdAt | string | ISO 创建时间 |
| deletedAt | string/null | 删除时间；null 为未删除，用于回收站 |
| filename | string，可选 | 批量导入时的文件名 |
| originalPath | string，可选 | 批量导入时原始本机路径 |

手工新增时地点、文字、照片至少有一项。照片最大 80 MB。图片资源为 `assets/<hash>.original`、`<hash>.preview`、`<hash>.thumb`，后缀是资源角色，不是图片格式。照片批量导入按内容 hash 检查重复。`migrations` 是已处理迁移标识列表。

示例（示意值）：

```json
{
  "version": 2,
  "migrations": [],
  "photos": [{
    "id": "point-1", "hash": null,
    "title": "西湖", "text": "傍晚沿湖散步",
    "date": "2026-11-16", "time": "17:30",
    "country": "中国", "region": "浙江", "city": "杭州", "cityId": "",
    "latitude": 30.25, "longitude": 120.15,
    "visitStatus": "visited", "locationStatus": "confirmed",
    "locationSource": "manual", "dateSource": "user",
    "createdAt": "2026-11-16T09:30:00.000Z", "deletedAt": null
  }],
  "journeys": [{"id": "journey-1", "title": "杭州之行", "note": "周末旅行", "pointIds": ["point-1"]}]
}
```

地球仪有独立备份/恢复：清单连同所引用的图片一起备份；恢复按 ID 增量合并，不覆盖同 ID 记录；校验原图 hash，并重建预览图。备份包含回收站中仍保留的记录及图片。

## 4. 书库与阅读器

`book.json`：

| 字段 | 类型 | 含义 |
|---|---|---|
| schemaVersion | number | 当前 2 |
| book.id / title / author / source | string | 书籍 ID、标题、作者、来源 |
| files | object[] | 该书文件清单 |
| files[].id | string | 文件名的 SHA256 |
| files[].role | string | `reading` 阅读正文 / `original` 原件 |
| files[].path / format | string | 相对文件名、扩展名 |
| files[].sha256 | string | 文件内容校验值 |
| files[].size | number | 文件字节数 |
| files[].modifiedAt | string | 文件修改时间 ISO |

正文单独存 `book.md`，原件可为 `original.md / .markdown / .txt / .pdf`。前端加载结果中的 `content` 和 `markdownFile:true` 是运行时字段，不在 `book.json.book` 内。旧 IndexedDB 为 `cyber-study-books` 数据库、`books` 对象仓库，当前用于遗留数据读取/迁移。

阅读器格式为 `{lastBookId, settings, books}`：`lastBookId` 为 string/null；`settings.fontSize`、`settings.lineHeight` 为 number；`books` 按书籍 ID 索引，每项保存 `title:string`、`progress:number`（整本进度）、`chapterProgress:number`（章节内进度）、`blockId`（正文块标识）、`updatedAt:string`。旧记录可能只含部分字段。

## 5. 知识库 / 摘录批注

顶层 `notes` 数组和 `projects` 数组；当前界面主要实现 notes，projects 仅见容器，未见完整项目创建及字段模型，不应视为已完成的创作项目模块。

| 笔记字段 | 类型 | 含义 |
|---|---|---|
| id | string | 笔记 ID |
| bookId / bookTitle | string | 关联书籍及书名副本 |
| quote / annotation | string | 摘录原文 / 用户批注 |
| tags | string[] | 标签，默认 [] |
| progress | number | 创建时阅读位置，默认 0 |
| blockId | string/null | 原文块定位 |
| side | string | 默认 left |
| markdownUnderline | boolean | 是否属于正文划线，默认 false |
| ranges | object[]，可选 | 精确范围，每项 `{blockId, start, end}`；start/end 为文字偏移 |
| source | string | 创建时设为书名 |
| createdAt | string | ISO 创建时间 |
| origin | string | 当前创建值 user |

界面兼容读取 `summary`、`chapterTitle`，但标准新增函数不生成这些字段。相同原文范围可能有多条批注记录，界面按书籍、块/进度、摘录和起点分组；没有独立“摘录主表 + 批注子表”。支持导出 Markdown。

## 6. 唱片机

| 歌曲字段 | 类型 | 含义 |
|---|---|---|
| id | string | 平台歌曲为 `provider:sourceId` |
| provider / sourceId | string | 平台、平台歌曲 ID |
| title / artist | string | 歌名、艺术家 |
| cover | string | 封面链接 |
| mediaMid / fee | 平台返回值，可选 | 平台播放解析所需信息 |
| cachedUrl | string，可选 | 已缓存音频地址，通常 study-audio 协议 |
| playlists | object[] | `{id:string, title:string, position:number}`，position 为顺序 |
| url / kind | string，可选 | 旧链接型数据及加载时识别的类型 |
| local | boolean，可选 | 本地临时导入标记 |

平台歌单 ID 组合为 `provider:listId`。导入歌单按歌曲 ID 合并，保留已有歌单成员关系和顺序。导入结果的 `cacheState` 不进入合并后的持久记录。

附属数据：`space.musicResume = {trackId, position, playlistId}`，position 是播放秒数；`space.musicPlaylistModes` 是按歌单索引的播放模式映射。音频文件在 `music-cache/`；账户凭据另存 `music-<provider>.enc`，不属于歌曲字段。

**本地文件夹导入的歌曲带 local:true 和临时 blob URL；写入 music 时明确过滤这些歌曲，因此重启不保留。** 无独立歌单主表，也意味着不能只按常规歌单表设计空歌单管理。

## 7. 影碟机 / 影像收藏

每条影片字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| id / title | string | ID、名称 |
| url | string | 播放来源网页链接，可为空 |
| status | string | 想看 / 在看 / 看过 |
| poster | string | 海报网址或 study-poster 本地资源地址 |
| douban | string | 豆瓣条目链接 |
| score | string | 豆瓣评分，注意存储为字符串，可空；填写时 0–10 |
| region | string[] | 国家/地区；兼容读取旧字符串 |
| genres | string[] | 类型 |
| tags | string[] | 用户标签，最多 5 个 |
| createdAt | string | ISO 创建时间 |

来源链接与豆瓣链接至少填写一个。海报落在 `movie-posters/`，通过 `study-poster://movie/<hash>.<扩展名>` 引用。当前收藏的是影片信息和网页链接，没有视频文件上传存储模型。

## 8. 日记、便签、打字机

| 数据块 | 字段与类型 |
|---|---|
| 日记 | `id:string, date:string(ISO), mood:string, text:string, photo:string` |
| 日记偏好 | `pen:string`（钢笔/羽毛笔）、`sound:boolean`、`animation:boolean`，保存在 `space.diary-prefs` |
| 便签公共字段 | `id:string, type:string, x:number, y:number`；调整大小后可有 `width:number, height:number` |
| 待办 type=todo | 额外 `text:string, done:boolean` |
| 文字便签 type=sticky | 额外 `text:string, tone:string` |
| 图片便签 type=image | 额外 `photo:string` |
| 打字机作品 | `id:string, textId:string, title:string, text:string, complete:boolean, createdAt:string` |

日记、便签的 photo 保存 Data URL（图片内容直接编码进字符串），不是文件引用。普通图片选择上限 2 MB；打字机转图片走生成路径。日记最多一个 photo；便签没有统一 createdAt/updatedAt 字段。打字机 textId 关联内置抄写文本，保存同一作品时 createdAt 也会重新赋值，当前不能把它严格当作永不变化的首次创建时间。

## 9. 植物与宠物

植物单对象：`growth:number` 生长值、`water:number` 水分、`waterings:number` 浇水次数、`focusMinutes:number` 累计专注分钟、`focusPeriods:number[][]` 专注时间段（每项开始/结束毫秒时间戳）、`lastWateredAt:string/null`、`updatedAt:number` 毫秒时间戳。加载返回的 `recentFocusMinutes` 为计算值，不是标准持久字段。旧水分刻度在初始化时换算为当前刻度。

宠物单对象：`mood:number` 心情、`bond:number` 亲密度、`pets:number` 抚摸次数、`lastPettedAt:string/null`、`moodTouches:number[]` 最近互动毫秒时间戳；互动后还写 `activePetId:string`（目前 cat）、`touchDay:string`（本地日期字符串）、`dailyCount:number`。心情/亲密度随时间计算变化；不是“每只宠物一条记录”的集合结构。

## 10. 设置与不产生内容数据的模块

- `cyber-study.shortcuts.v2`：动作 ID 到快捷键字符串数组的映射，兼容读取旧版 `v1`。
- `study-graphics`：画质设置对象，含 dpr、textures、shadowSize、rain、glows、antialias，以及可选 mode；兼容旧预设名称。
- 灯、窗户以及场景切换等是场景交互，不对应用户新增内容集合。场景包、模型、地理底图、内置示例书/抄写文本属于静态资源与配置，应与用户内容分开管理。

## 11. 对数据管理设计的直接影响

1. 目前无法用单个 localStorage 导出覆盖所有数据：必须同时处理书籍、地球仪照片、音频缓存、海报和各本地存储键。地球仪独立备份只覆盖自身。
2. 目前没有统一 userId、schemaVersion、createdAt、updatedAt、deletedAt；版本号有的在键名中，有的在 JSON 内。只有地球仪明确实现软删除数据字段，不能假设所有模块都有回收站。
3. 关系主要靠 ID 和应用代码维护，没有统一外键及跨模块删除规则。规划“删除书籍是否保留笔记”“删除旅程是否删点”等操作时需逐项明确。
4. 图片保存策略不同：地球仪/海报是文件引用，日记/便签是内嵌图片；后者受 localStorage 容量限制。统一附件管理是后续设计项，尚未实现。
5. “一个记忆点多张照片”“独立空歌单”“多宠物记录”“统一导入导出与同步”都需要扩展当前模型，不能仅增加界面入口。
